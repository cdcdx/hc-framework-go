# 901 · API 参考(go-zero 版)

> 网关统一响应结构:HTTP 200 时 `{code, message, data, trace_id}`(业务失败也多为 200 + 业务错误码,
> 鉴权/限流/参数错误等按语义返回 401/403/400/429/503)。分页接口 data 为
> `{items, next_cursor, has_more}`。所有时间字段均为 unix 秒。
> 鉴权方式:`Authorization: Bearer <access_token>`(user_id 由网关从 token 解析,客户端无需传)。

## 1. 系统接口

### 1.1 GET /health
健康检查。

```json
{ "code": 0, "message": "success", "data": { "status": "ok" }, "trace_id": "..." }
```

### 1.2 GET /ready
就绪检查。

```json
{ "code": 0, "message": "success", "data": { "status": "ready" }, "trace_id": "..." }
```

### 1.3 GET /api/v1/captcha/config
验证码前端配置(未启用时 enabled=false)。

```json
{ "code": 0, "message": "success",
  "data": { "enabled": false, "provider": "turnstile", "site_key": "", "script_src": "..." } }
```

### 1.4 POST /api/v1/auth/refresh
用 refresh_token 换新 token 对。

| 字段 | 类型 | 必填 |
|---|---|---|
| refresh_token | string | 是 |

成功响应 data:`{ access_token, refresh_token }`。失败:`10102 token 无效`。

## 2. 认证接口(防水墙组:IP 限频 → 验证码)

### 2.1 POST /api/v1/auth/register
邮箱注册,成功直接签发 token。

| 字段 | 类型 | 必填 |
|---|---|---|
| email | string | 是 |
| password | string | 是(≥8 位) |
| username | string | 否(缺省取 email) |
| captcha_token | string | 验证码启用时必填 |

成功 data:`{ user: {...}, access_token, refresh_token }`。错误码:`10201 邮箱已注册`。

### 2.2 POST /api/v1/auth/login
邮箱密码登录,成功后自动推进 `daily_login` 任务进度。

| 字段 | 类型 | 必填 |
|---|---|---|
| email | string | 是 |
| password | string | 是 |
| captcha_token | string | 验证码启用时必填 |

成功 data:`{ user: {...}, access_token, refresh_token }`。错误码:`10202 密码错误`(不泄露账号是否存在)、`10203 账号锁定`。

## 3. Google OAuth

### 3.1 POST /api/v1/auth/google
Google 授权码登录/注册(自动注册)。

| 字段 | 类型 | 必填 |
|---|---|---|
| code | string | 是 |

成功 data:`{ user: {...}, access_token, refresh_token }`。错误码:`10704 第三方服务异常`。

## 4. 用户接口(需鉴权)

### 4.1 PUT /api/v1/user/password
修改密码(校验旧密码;改密后已签发 token 失效)。

| 字段 | 类型 | 必填 |
|---|---|---|
| old_password | string | 是 |
| new_password | string | 是(≥8 位) |

成功 data:`{ "message": "password changed" }`。错误码:`10202 旧密码错误`。

### 4.2 GET /api/v1/user/profile
用户资料。

成功 data(用户对象):`{ user_id, username, email, avatar_url, points_balance, status, created_at }`。

### 4.3 PUT /api/v1/user/profile
更新资料(昵称 ≤50、头像 URL ≤500)。

| 字段 | 类型 | 必填 |
|---|---|---|
| username | string | 否 |
| avatar | string | 否 |

成功 data:用户对象(同 4.2)。

### 4.4 GET /api/v1/user/points
积分余额。

成功 data:`{ user_id, points_balance }`。

## 5. 挂机接口(需鉴权)

### 5.1 POST /api/v1/idle/start
开始挂机(同设备幂等返回现有会话;设备数上限 3)。

| 字段 | 类型 | 必填 |
|---|---|---|
| device_id | string | 是 |

成功 data(挂机记录):`{ id, user_id, device_id, start_time, end_time, duration_seconds, points_earned, status, last_heartbeat_at }`。错误:`10401 已在挂机`。

### 5.2 POST /api/v1/idle/heartbeat
心跳上报(心跳超时 5 分钟自动结算为 timeout,需重新 start)。

| 字段 | 类型 | 必填 |
|---|---|---|
| device_id | string | 是 |

成功 data:`{ "status": "alive" }`。错误:`10402 未在挂机`、`10404 心跳超时`。

### 5.3 POST /api/v1/idle/stop
停止全部设备挂机并结算(1 积分/分钟,每日上限 240)。

成功 data:最后结算的记录。错误:`10402 未在挂机`、`10405 已达每日积分上限`。

### 5.4 POST /api/v1/idle/stop-device
停止指定设备并结算。

| 字段 | 类型 | 必填 |
|---|---|---|
| device_id | string | 是 |

成功 data:结算记录。

### 5.5 GET /api/v1/idle/status
活跃会话 + 今日已赚积分。

成功 data:`{ records: [...], today_points }`。

### 5.6 GET /api/v1/idle/records
历史记录(游标分页)。

| 参数 | 类型 | 必填 |
|---|---|---|
| cursor | int64 | 否(上一页 next_cursor) |
| limit | int | 否(默认 20,≤100) |

成功 data(分页):`{ items: [...], next_cursor, has_more }`。

## 6. 任务接口(需鉴权)

任务周期:daily=当天、weekly=ISO 周、achievement=永久。

### 6.1 GET /api/v1/tasks
任务列表(含当前进度)。

成功 data:`{ tasks: [ { id, task_type, task_key, task_name, target_value, reward_points, is_active, current_progress, is_completed, is_claimed, period } ] }`。

### 6.2 GET /api/v1/tasks/progress
进度总览(结构同 6.1)。

### 6.3 POST /api/v1/tasks/:id/claim
领取任务奖励(进度达标且未领取)。

成功 data:`{ task: {...}, reward_points }`。错误:`10501 任务未完成`、`10502 已领取`。

## 7. 商城接口(需鉴权)

### 7.1 GET /api/v1/shop/items
商品列表(游标分页 + 分类筛选)。

| 参数 | 类型 | 必填 |
|---|---|---|
| cursor | int64 | 否 |
| limit | int | 否(默认 20,≤100) |
| category | string | 否 |

成功 data(分页):`{ items: [ { id, name, description, price_points, stock, image_url, category, is_active, sales_status } ], next_cursor, has_more }`。

### 7.2 POST /api/v1/shop/redeem
积分兑换(原子扣库存 + 扣积分 + 建单,失败自动回滚库存)。

| 字段 | 类型 | 必填 |
|---|---|---|
| item_id | int64 | 是 |
| quantity | int32 | 否(默认 1) |

成功 data:`{ order: { id, user_id, item_id, item_name, points_spent, order_status, activity_id, created_at } }`。
错误:`10303 商品下架`、`10302 库存不足`、`10301 积分不足`。

### 7.3 GET /api/v1/shop/orders
兑换订单列表(分页,参数同 7.1)。

### 7.4 GET /api/v1/shop/orders/:id
订单详情(校验归属,非本人返回 403/10103)。

### 7.5 GET /api/v1/shop/flash/activities
进行中的抢购活动列表。

成功 data:`{ activities: [ { id, item_id, name, start_time, end_time, limit_qty, sold_qty, per_user_limit, price_points, status, sales_status } ] }`。

### 7.6 POST /api/v1/shop/flash/redeem
定时抢购(时间窗内原子抢配额,限量内入库)。

| 字段 | 类型 | 必填 |
|---|---|---|
| activity_id | int64 | 是 |

成功 data:`{ order: {...} }`。
错误:`10305 未开始`、`10306 已结束`、`10307 已抢光`、`10308 超限购`、`10301 积分不足`。

## 8. 错误码速查

| 区间 | 含义 |
|---|---|
| 10001-10005 | 参数/不存在/未知/超时/服务不可用 |
| 10101-10104 | token 过期/无效/权限不足/token 失效 |
| 10201-10205 | 邮箱已注册/密码错误/账号锁定/禁用/需验证码 |
| 10301-10311 | 积分不足/库存不足/下架/重复兑换/抢购未开始·结束·售罄·限购·超时·并发·削峰售罄 |
| 10401-10405 | 已在挂机/未挂机/踢下线/心跳超时/每日上限 |
| 10501-10504 | 任务未完成/已领取/过期/进度不足 |
| 10601-10603 | 限流/熔断/验证码失败 |
| 10701-10704 | DB/Redis/Kafka/第三方异常 |

完整错误码与默认消息见 `common/errorx/errorx.go`。
