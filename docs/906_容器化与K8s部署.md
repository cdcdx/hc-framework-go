# 906_容器化与 K8s 部署（go-zero 合并单进程 hc-server）

> 适用分支 `feature/go-zero-migration`。本文描述 **go-zero 版** 的容器化与 K8s 部署，
> 与 gin 版的多进程部署（`401_集群设备部署手册.md`）架构不同，勿混用。
> 实际配置入口为 **`config/server.yaml`**（顶层 `Gateway` + `Rpc` 两段），不是历史文档里提到的 `hc.yaml` / `gateway.yaml`。

## 1. 进程模型

go-zero 版已将 **Gateway(REST) 与后端 logic 合并为单进程 `hc-server`**（入口 `app/server/cmd`）。

- REST 监听 `:8080`（`config/server.yaml` → `Gateway.Host/Port`）
- Prometheus 指标同端口 `/metrics`（`prometheus.Enable()`，无需额外端口）
- 旧的对外部署 gRPC 接口（`:8001` / etcd 服务发现）**已移除**；网关通过进程内 `LocalHcClient` 直接调用后端逻辑
- 因此**只需一个容器 / 一个 Deployment** 即可承载全部业务

## 2. 镜像构建

### 2.1 Dockerfile（已更新）

`Dockerfile` 已改为构建合并单进程：

```dockerfile
FROM golang:1.25-alpine AS builder
RUN apk add --no-cache gcc musl-dev        # CGO（sqlite）需要 gcc
WORKDIR /src
COPY go.mod go.sum ./ && RUN go mod download
COPY . .
RUN CGO_ENABLED=1 GOOS=linux go build -o /out/hc-server ./app/server/cmd

FROM alpine:3.20
RUN apk add --no-cache ca-certificates tzdata \
 && addgroup -S hc && adduser -S hc -G hc
WORKDIR /app
COPY config/ ./config/
COPY deployments/docker-entrypoint.sh ./docker-entrypoint.sh
COPY --from=builder /out/hc-server ./hc-server
EXPOSE 8080
USER hc
ENTRYPOINT ["./docker-entrypoint.sh"]
```

要点：
- 启用 **CGO**（`CGO_ENABLED=1`），因为 `common/dbclient` 默认驱动依赖 `mattn/go-sqlite3`
- 配置目录 `config/` 整体复制进镜像根（`/app/config/`）
- 启动入口 `deployments/docker-entrypoint.sh` 加载 `/app/config/server.yaml`，并用 `exec` 替换进程以保证 `SIGTERM` 直达（go-zero 优雅关闭）

### 2.2 本地构建命令

```bash
# 等价于 Makefile build-server，但产出镜像
docker build -t hc-framework:latest .

# 运行（本地数据卷可选）
docker run --rm -p 8080:8080 \
  -v "$PWD/config:/app/config:ro" \
  hc-framework:latest
```

> 也可直接用 `make build-server && ./bin/hc-server -f config/server.yaml` 本地裸跑，见 `601_测试与开发指南.md`。

## 3. K8s 部署清单

`deployments/hc-server.yaml` 提供一份开箱即用的清单（ConfigMap + Deployment + Service）：

| 资源 | 名称 | 说明 |
|:---|:---|:---|
| ConfigMap | `hc-server-config` | 内嵌 `server.yaml`（sqlite 单文件 + 进程内 MQ，开箱即用） |
| Deployment | `hc-server` | 1 副本，就绪探针 `/ready`、存活探针 `/health`，挂载 ConfigMap 与 `emptyDir` 数据卷 |
| Service | `hc-server` | ClusterIP `:8080` |

配套注解已声明 Prometheus 抓取：

```yaml
annotations:
  prometheus.io/scrape: "true"
  prometheus.io/port: "8080"
  prometheus.io/path: "/metrics"
```

### 3.1 一键部署

```bash
# 构建镜像并推送到集群可访问的仓库（或本地 kind/minikube load）
docker build -t hc-framework:latest .
# 若为本地集群：
kind load docker-image hc-framework:latest        # kind
# 或 minikube：
minikube load-image hc-framework:latest           # minikube

# 应用（build.sh docker 内部即执行此命令）
kubectl apply -f deployments/hc-server.yaml
```

> `build.sh docker` 当前执行 `docker build -t hc-framework:latest . && kubectl apply -f deployments/`。
> 注意 `deployments/` 下还包含 MySQL/Redis/Mongo/Kafka/ClickHouse/ES 等**中间件** yaml，
> 按需先 apply 对应中间件，再 apply 本应用清单。

### 3.2 生产化注意点

- **持久化**：示例用 `emptyDir`，重启即丢。生产应：
  - 改用 MySQL/Postgres（改 `Rpc.Databases.*.Driver/Dsn`，表结构与 `migrations/` 一致），或
  - 用 `PersistentVolumeClaim` 挂载 `/data` 以保留 sqlite 文件
- **配置覆盖**：示例中 JWT `SigningKey` 为占位值，生产请通过 Secret 挂载覆盖 ConfigMap，勿把密钥写进镜像
- **多副本**：当前限流/IP 频控为进程内窗口，**多副本不共享计数**；如需多副本，按 `900_go-zero迁移说明.md` §6 升级为 Redis 令牌桶
- **资源**：requests 250m/256Mi、limits 2/1Gi，可按压测结果调整（压测见 `k6-test.sh`）
