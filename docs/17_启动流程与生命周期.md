# 启动流程与生命周期

> 本文描述进程从启动到优雅关闭的完整生命周期。代码入口已下沉到 `internal/bootstrap`（`App.Run()`），`cmd/server/main.go` 仅为薄入口（`os.Exit(bootstrap.Run())`）。相比旧版「上帝文件」main.go（944 行），装配逻辑现集中在组合根包，可独立测试（见 `internal/bootstrap/bootstrap_test.go`）。
>
> 相关：组合根代码见 `internal/bootstrap/app.go` 与 `internal/bootstrap/bootstrap.go`；架构模块划分见 `03_架构说明.md`；本次下沉的优化记录见 `13_代码优化记录.md`。

## 一、入口

- `cmd/server/main.go`：解析 `-config`（默认 `config/config.yaml`）后调用 `bootstrap.Run()`，以其返回码作为进程退出码。
- `bootstrap.Run()`：解析 flag → `newApp` 加载配置与日志 → `App.run()` 编排整个生命周期。
- `newApp` 在 logger 初始化**之前**加载配置（`config.LoadManager`），失败则打印到 stderr 并以退出码 1 返回（此时尚无结构化日志）。

## 二、启动顺序（`App.run` 编排）

> `App.run()` 是纯编排器，依次调用下列 `App` 阶段方法（`initTracing` / `initJWT` / `initCache` / `initServices` / `startBackgroundTasks` / `initScheduler` / `startHTTP`），各方法只做「一件事」，便于单独审视与单测（见第四节）。下方序号与代码中的阶段一致。

1. **配置热更新监听**：`cfgMgr.Watch(ctx)`（SIGHUP 信号 + 文件监听）。
2. **链路追踪 Provider**：按 `tracing.exporter`（otlp / stdout / none）初始化，`trace.SetGlobal` 注册。
3. **数据库**：`InitDatabases(cfg)` 初始化 business / user / monitor / log / login 五库（支持读写分离与多驱动回退 SQLite），返回 `*Databases`。
4. **JWT 管理器**：`service.InitJWT`。
5. **缓存管理器**：`cache.NewManager(cfgMgr, zlog)`，并注入为 Token 黑名单检查器（`middleware.SetBlacklistChecker`）。
6. **LogService**：聚合 log / monitor / login 仓库。
7. **事件生产者 / 消费者**：`mq.NewProducer` / `mq.NewConsumer`（工厂按 `mq.type` 分派；`none` 返回 no-op）。kafka 走 `EnsureTopics` 幂等建 topic。
8. **账号锁定存储**：L2 可用时复用 `cacheMgr`（跨 Pod 共享），否则进程内实现。
9. **邮件发送器**：仅 `mail.enabled` 时创建。
10. **业务服务装配**：`AuthService` / `PointsOutboxApplier` / `IdleService` / `TaskService` / `ShopService`；`PointsOutboxApplier.RelayLoop` 随 `bgCtx` 后台运行（最终一致兜底）。
11. **写降级事件发送器**：仅 `mq.IsEnabled` 时注入 `cacheMgr.SetDegradeSender`。
12. **种子数据 + 挂机索引 / 活跃会话回填 + 事件驱动结算 + 心跳批量落库定时器**。
13. **调度器 `scheduler.New()` + 选主 `cluster.NewLeaderElector`**（L2 可用时）；死分片接管、副本发现随 `bgCtx` 后台运行。
14. **调度任务注册**：idle 超时扫描、每日 / 每周任务重置、事件去重清理（选主启用时仅 Leader 执行）。
15. **依赖注入容器 `handler.Dependencies` + `router.Setup(deps)`**。
16. **HTTP Server 启动**：显式设置 `ReadTimeout` / `ReadHeaderTimeout` / `WriteTimeout` / `IdleTimeout`（避免 keep-alive 被误关导致客户端复用连接报 EOF）。

## 三、优雅关闭（`App.shutdown`）

收到 SIGINT / SIGTERM 后按序释放，**每步带耗时日志**（谁慢一目了然，消除旧版「退出观感慢」的根因——关闭动作曾藏在静默 `defer` 里）：

1. **HTTP Server**：`srv.Shutdown`，超时则强制 `Close`（不再 Fatal 中断后续清理）。
2. **后台协程**：`bgCancel()` 统一取消 RelayLoop / Kafka 订阅 / 死分片接管 / 副本发现。
3. **限流器后台清理**：`middleware.StopRateLimiter()` 停止 cleanup ticker（避免 goroutine 泄漏）。
4. **事件驱动结算**：`idleSvc.StopEventDriven`。
5. **心跳批量落库 drain**：`idleSvc.StopHeartbeatFlush(ctx)`（HTTP 已停，可安全 flush 剩余心跳）。
6. **调度器**：`sched.Stop()` 等待进行中任务完成。
7. **选主锁释放**：`leader.Stop()`（尽快让出 Leader，加速其他副本接管）。
8. **事件消费者 / 生产者**：`Close()`（生产者内置 5s 超时兜底，broker 不可达也不拖死退出）。
9. **日志 / 监控**：`logSvc.Close`（排空异步缓冲）。
10. **链路追踪**：`trace.Global().Shutdown(ctx)`（flush 残余 span）。
11. **缓存与数据库**：`cacheMgr.Close` + `dbs.Close()`（统一释放 business/user/monitor/log/login 五类连接，放在最后，确保上层协程已停止读写）。

> 关闭序列的可测试性与可观测性由 `13_代码优化记录.md` §2.7 记录；本次把该序列从 main.go 下沉到 `bootstrap.App.shutdown`（§3.32）。

## 四、可测试性（组合根下沉的直接收益）

原先堆在 main.go 的逻辑被拆为可独立测试的函数（`internal/bootstrap/bootstrap_test.go`）：

- `extractAddrDB` / `dsnAddr` / `safeConnFields`：DSN 脱敏解析（层级 URL 取 host+db，文件型取路径为连接位置）。
- `IdleScanInterval`：离线扫描间隔钳制到 `[timeout/3, 2*timeout]`。
- `openGORMOrFallback` / `rwOpenGORM`：主库不可用时回退 SQLite（`driver==sqlite` 不二次回退，避免掩盖配置错误）。

覆盖 DSN 解析（mysql / postgres / sqlite 三种形态）、扫描间隔钳制边界、以及 DB 回退路径的失败 / 成功分支。
