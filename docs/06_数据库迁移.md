# 数据库迁移（Migrations）

> 本框架使用 [golang-migrate](https://github.com/golang-migrate/migrate) 管理 SQL 类存储的表结构演进，按「数据域 / 驱动」分层组织迁移文件。本文档是迁移机制的单一来源；配置项见 [05_配置参考.md](./05_配置参考.md)。

---

## 一、机制概述

- 四个数据域相互独立：`user`（用户）、`business`（业务）、`log`（审计日志）、`monitor`（监控）。
- 每域按驱动分子目录：`migrations/<域>/<驱动>/`，仅 **SQL 类驱动**（`mysql`/`postgres`/`sqlite`/`clickhouse`）走 golang-migrate。
- **非 SQL 驱动无需迁移文件**：`mongodb`（集合/索引由驱动运行时自管理）、`elasticsearch`（索引由驱动自管理），`make migrate` 会自动跳过并提示。
- DSN 统一从 `config.yaml` 读取，环境变量 `APP_DATABASE_<域>_DRIVER` 与对应 `*_MASTER` 可覆盖。
- 迁移脚本：`scripts/migrate.sh`（由 `make migrate` 调用）。

---

## 二、目录结构

```
migrations/
├── business/                # 业务域
│   ├── mysql/               # 2 文件（initial_schema up/down，已整合全部迁移）
│   ├── postgres/            # 2 文件
│   └── sqlite/              # 2 文件（本地回退）
├── user/                    # 用户域
│   ├── mongodb/             # 0 文件（运行时自管理，无需迁移）
│   └── sqlite/              # 2 文件（initial_schema up/down）
├── log/                     # 日志域
│   ├── elasticsearch/       # 0 文件（索引自管理）
│   └── sqlite/              # 2 文件
└── monitor/                 # 监控域
    ├── clickhouse/          # 2 文件（initial_schema up/down）
    └── sqlite/              # 2 文件
```

## 三、使用命令

```bash
# 全部域全部迁移（up）
make migrate

# 指定域 up / down
make migrate up business
make migrate down user

# 指定单个域（Make 变量 DB）
make migrate DB=business        # 等价于 up business
make migrate down DB=monitor
```

等价原生调用（脚本负责 DSN 转换，含 ClickHouse 特有格式）：

```bash
bash scripts/migrate.sh up all
bash scripts/migrate.sh down business
```

> 参数解析：`up`/`down` 指定方向；`user`/`business`/`log`/`monitor`/`all` 指定范围。非 SQL 驱动域会被自动跳过（如 `user` 用 `mongodb` 时仅处理 `sqlite` 回退）。

---

## 四、命名约定

每个迁移是一对的 `.up.sql` / `.down.sql`，文件名前缀为时间戳版本号：

```
<YYYYMMDD>_<描述>.up.sql      # 正向（建表/加列/加索引）
<YYYYMMDD>_<描述>.down.sql    # 回滚（反向）
```

示例（当前已落地）：
- `20260708_initial_schema.up.sql` / `.down.sql` — 各域初始表结构 + 业务域默认任务种子数据 + 消费侧进度表 + 索引优化（已整合为单一迁移）

新增迁移时复制该命名，版本号递增即可，golang-migrate 按文件名顺序执行并在 `schema_migrations` 表记录版本。

|--------|------|----------|------|

| log | sqlite | ✅ 2 文件 | initial_schema |
| log | elasticsearch | —（跳过） | 索引运行时自管理 |

## 六、自动迁移与生产建议

| 配置项 | 默认值 | 建议 |
|--------|--------|------|
| `migration.enabled` | `true` | 开启迁移能力 |
| `migration.auto_migrate` | `true` | **开发环境开启；生产环境建议关闭**，改用 `make migrate` 受控执行，避免未评审的 DDL 随启动自动落地 |
| `migration.path` | `./migrations` | 迁移根目录 |

> 生产发布建议流程：CI 评审 SQL → 停机窗口或低峰期 `make migrate up <域>` → 验证 → 滚动发布应用。回滚时 `make migrate down <域>` 到上一版本。

## 七、常见问题

- **`no change` / 已是最新版**：golang-migrate 记录版本，重复 `up` 幂等，属正常。
- **迁移失败中途退出**：golang-migrate 不会自动回滚；需先 `make migrate down <域>` 到干净版本，修正 SQL 后重新 `up`。
- **ClickHouse DSN 报错**：脚本会自动把 `clickhouse://user:pass@host:port/db` 转为 golang-migrate 需要的 `host?username=&password=&database=&x-multi-statement=true` 格式，无需手改。
- **mongodb/elasticsearch 域提示「跳过」**：正常现象，非 SQL 驱动无表结构迁移。
