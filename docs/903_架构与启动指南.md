# 903 · 架构与启动指南(go-zero 版)

## 1. 架构总览

```
                         ┌──────────────────┐
   HTTP :8080 ─────────► │  gateway-api     │  rest 网关(go-zero)
                         │  中间件链:        │
                         │  JwtAuth          │  校验 token → 注入 user_id
                         │  SecurityIPLimit  │  注册/登录 IP 限频
                         │  Captcha          │  注册/登录验证码防水墙
                         │  统一响应          │  {code,message,data,trace_id}
                         └────────┬─────────┘
                                  │ gRPC(zrpc) + etcd 服务发现
                         ┌────────▼─────────┐
                         │  hc-rpc          │  单一领域服务(gRPC :8001)
                         │  user / idle /   │
                         │  task / shop     │  四域合并,域间进程内调用
                         └────────┬─────────┘
                                  │ gorm
                         ┌────────▼─────────┐
                         │  DB(sqlite/mysql/postgres) + Redis(可选)
                         └──────────────────┘
```

**2 个进程**:`hc-rpc`(业务 + 数据)+ `gateway-api`(HTTP 入口与横切治理)。

## 3. 首次生成与启动

前置:Go ≥ 1.22;protoc + protoc-gen-go + protoc-gen-go-grpc;etcd(可选,直连模式见 902 §3)。

```bash
# 3.1 生成 pb 代码(生成 app/rpc/hc/hc.pb.go 与 hc_grpc.pb.go)
make gen
# 等价命令:
#   protoc --go_out=. --go_opt=paths=source_relative \
#          --go-grpc_out=. --go-grpc_opt=paths=source_relative app/rpc/hc.proto

# 3.2 收敛依赖
go mod tidy

# 3.3 编译验证
make build          # 产物 bin/hc-rpc、bin/gateway-api

# 3.4 启动(需 etcd)
make run            # 先 hc-rpc 后 gateway-api

# 或分别启动
make run-hc         # cd app/rpc && go run hc.go -f etc/hc.yaml
make run-gateway    # cd app/gateway/api && go run gateway.go -f etc/gateway.yaml
```

启动后自检:

```bash
curl http://localhost:8080/health
curl http://localhost:8080/ready
curl -X POST http://localhost:8080/api/v1/auth/register \
     -H 'Content-Type: application/json' \
     -d '{"email":"a@b.com","password":"12345678"}'
```

## 4. 调用链路示例

**注册**:`POST /api/v1/auth/register`
1. 网关:SecurityIPLimit → Captcha(未启用则跳过)
2. handler 绑定参数 → RegisterLogic
3. `HcRpc.Register`(gRPC)→ hc-rpc RegisterLogic:查重 → bcrypt → 建用户 → 签发 token
4. 返回 `{user, access_token, refresh_token}`,网关统一包装响应

**挂机结算**:`POST /api/v1/idle/stop`
1. 网关 JwtAuth 校验 → IdleStopLogic → `HcRpc.IdleStop`
2. hc-rpc StopLogic:查活跃会话 → `settle()`:
   - 计算积分 → 每日上限累加(`idle_daily_points`)
   - **进程内**调用 AddPointsLogic 入账(user 域)
   - **进程内**调用 ReportProgressLogic 上报 `daily_idle_30`/`weekly_idle_300`
   - 落库更新记录

**抢购**:`POST /api/v1/shop/flash/redeem`
1. 网关鉴权 → FlashRedeemLogic → `HcRpc.FlashRedeem`
2. hc-rpc FlashRedeemLogic:时间窗/限购校验 → 原子抢配额(`sold_qty<limit_qty`)→
   **进程内** DeductPoints 扣款(失败回滚配额)→ 建单 → 上报兑换任务进度

## 5. 部署要点

- **无状态**:两个服务均为无状态进程,可多副本;网关 IP 限频为进程内窗口,**多副本需改为 Redis 限流**。
- **数据库**:多副本共享同一数据库实例;sqlite 仅限单机开发。
- **etcd**:生产建议独立 etcd 集群;或网关改用 K8s Service 直连(`direct://hc-rpc:8001`)。
- **优雅关闭**:go-zero rest/zrpc 自带优雅关闭,配合 K8s 探针(`/health`、`/ready`)实现滚动发布。
- **可观测**:两端均暴露 Prometheus 指标(网关 :9100 / hc-rpc :9101),链路追踪由 go-zero 内置 OTel 支持。
