# 905 运维与监控：重启、指标验证

适用于 go-zero 版合并单进程部署 `hc-server`（仅暴露 REST `:8080`，指标经 `:8080/metrics`）。

## 1. 指标端点验证（先确认监控数据源）

```bash
# 健康检查
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/health
# 拉取指标（Prometheus 抓取目标）
curl -s http://localhost:8080/metrics | grep -E "^(http_server_requests_code_total|http_server_requests_duration_ms|go_goroutines|process_resident_memory_bytes|db_pool_utilization|shop_flash_redeem_total)"
```

> ⚠️ **指标生效前提**：go-zero 的原生 HTTP 指标（`http_server_requests_*`）**不会自动注册**。其 `core/metric` 包在 `prometheus.Enabled()` 为 false 时会直接跳过注册。
> 必须在 `app/server/cmd/main.go` 启动网关前调用 `prometheus.Enable()`（已加，见代码）。若发现 `/metrics` 里完全没有 `http_server_requests_*` 系列，优先检查该调用是否被移除。

关键指标一览：

| 指标 | 来源 | 说明 |
|------|------|------|
| `http_server_requests_code_total{code,method,path}` | go-zero 自带 | HTTP 请求计数，告警错误率/P99 基于此（注：go-zero 实际指标名是 `code_total`，非 `requests_total`） |
| `http_server_requests_duration_ms_bucket` | go-zero 自带 | HTTP 延迟直方图（毫秒） |
| `go_goroutines` / `go_memstats_*` / `process_*` | go runtime | 资源类告警 |
| `db_pool_utilization{db}` / `db_pool_wait_count_total{db}` | 本项目 `gormx` | 连接池利用率/等待数（生产 mysql/postgres 生效；sqlite 因驱动语义可能不报） |
| `shop_flash_redeem_total` / `shop_flash_redeem_timeout_total{reason}` | 本项目 `FlashRedeem` | 抢购总量与超时（10309）计数 |
| `idle_scan_duration_seconds` | 本项目已注册 | 挂机扫描耗时，待 idle 扫描逻辑埋点 |

## 2. 应用进程重启

### 2.1 裸进程 / 开发（Makefile）

```bash
make build-server          # 编译 bin/hc-server
make run-server            # go run 前台启动（日志打印到终端）
make kill                  # fuser -k 释放 8080/8001
make restart-server        # kill + build + run（开发热重启）
```

> 裸进程无守护，**崩溃不会自动拉起**，仅适合开发/临时验证。

### 2.2 systemd（推荐生产，自动重启）

`/etc/systemd/system/hc-server.service`：

```ini
[Unit]
Description=hc-server (go-zero 合并单进程)
After=network.target postgresql.service

[Service]
Type=simple
User=hc
WorkingDirectory=/opt/hc-framework
ExecStart=/opt/hc-framework/bin/hc-server -f /opt/hc-framework/config/server.yaml
Restart=on-failure
RestartSec=3
# 优雅停机：SIGTERM 后 go-zero rest 会等待在途请求
KillSignal=SIGTERM
TimeoutStopSec=30
Environment=GOMAXPROCS=4

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now hc-server
sudo systemctl restart hc-server     # 重启（平滑替换）
sudo systemctl status  hc-server
journalctl -u hc-server -f           # 看日志
```

### 2.3 Supervisor（无 systemd 环境）

`/etc/supervisor/conf.d/hc-server.conf`：

```ini
[program:hc-server]
command=/opt/hc-framework/bin/hc-server -f /opt/hc-framework/config/server.yaml
directory=/opt/hc-framework
autostart=true
autorestart=true
startretries=3
user=hc
stdout_logfile=/var/log/hc-server/out.log
stderr_logfile=/var/log/hc-server/err.log
```

```bash
sudo supervisorctl reread && sudo supervisorctl update
sudo supervisorctl restart hc-server
```

### 2.4 Kubernetes

```yaml
# Deployment 片段
containers:
- name: hc-server
  image: registry.local/hc-framework:latest
  args: ["-f", "/etc/hc/config/server.yaml"]
  ports: [{containerPort: 8080}]
  readinessProbe:
    httpGet: {path: /health, port: 8080}
    initialDelaySeconds: 5
    periodSeconds: 10
  livenessProbe:
    httpGet: {path: /health, port: 8080}
    initialDelaySeconds: 10
    periodSeconds: 15
  resources:
    requests: {cpu: "500m", memory: "256Mi"}
    limits:   {cpu: "2",    memory: "1Gi"}
```

滚动重启：`kubectl rollout restart deployment/hc-server`；Pod 崩溃由 kubelet 自动拉起。

## 3. 监控栈重启（Prometheus / Alertmanager / Grafana）

### 3.1 docker-compose（deployments/docker-compose.monitoring.yml）

```bash
cd deployments
docker compose -f docker-compose.monitoring.yml up -d        # 首次/启动
docker compose -f docker-compose.monitoring.yml restart      # 重启全部组件
docker compose -f docker-compose.monitoring.yml restart prometheus  # 仅重启 Prometheus
docker compose -f docker-compose.monitoring.yml ps
```

### 3.2 Prometheus 配置热加载（改了 rules/*.yaml 不必重启）

```bash
# 方式一：API 热加载（需 prometheus 启动时带 --web.enable-lifecycle）
curl -XPOST http://localhost:9090/-/reload

# 方式二：改了 prometheus.yml 静态 target，必须重启 prometheus 容器
docker compose -f deployments/docker-compose.monitoring.yml restart prometheus
```

### 3.3 告警规则与抓取对齐要点（已修正）

- scrape job 名已统一为 `hc-server`（`deployments/prometheus/prometheus.yaml`），`ServiceDown` 规则 `up{job="hc-server"}==0` 才能正确触发。
- HTTP 错误率/P99 告警改用 go-zero 真实指标 `http_server_requests_code_total{code=~"5.."}` 与 `http_server_requests_duration_ms_bucket`（注意 go-zero 实际是 `code_total` 而非 `requests_total`）。
- 抢购超时告警 `shop_flash_redeem_timeout_total` 已在本仓库 `FlashRedeem` 埋点（见 `common/metrics`、`app/rpc/logic/flashredeemlogic.go`）。
- `db_pool_*` 指标由 `common/gormx.OpenWithPool` 后台采集，需 `config` 中 `DB.MaxOpenConns > 0`（生产必配，否则连接数无上限）。
- `MQ / cache / scheduler / circuit_breaker / rate_limit / idle_scan` 相关休眠规则暂无对应埋点，不会误报，待子系统接入后自动生效。

## 4. 故障排查清单

1. 指标 endpoint 404？—— 合并后只有 `:8080/metrics`（网关 routes.go 注册的 promhttp），不再有独立 `:9101`。
2. `ServiceDown` 误报？—— 检查 Prometheus target 的 `job` 标签是否为 `hc-server`。
3. `db_pool_*` 不出现？—— sqlite 驱动下 `MaxOpenConnections` 可能为 0，生产换 mysql/postgres 即可；确认 `server.yaml` 的 `Rpc.DB.MaxOpenConns>0`。
4. 进程起不来？—— 看日志是否 `field X is not set`（go-zero `conf.MustLoad` 强校验，所有字符串字段需在 yaml 显式提供，含空串）。
