## 单一来源约定（SSOT）
- **需求**：`01` = 基线；`02` = 权威。`01` / `02` 是**刻意的两级结构**（基线摘要 vs 详细规格），非冗余；重叠章节以 `02` 为准，`01` 仅保留基线视角摘要并交叉引用。**两者不合并**。
- **接口 / 错误码**：`04` 为权威（路由以代码为准；数据模型字段以 `02 §6` 为准）。
- **配置**：`05` 为权威。
- **容量评估**：根 `README.md`「百万设备容量评估」仅保留结论与链接，详情见 `07`。
- **部署清单**：`03 §七` 仅作索引，完整 `deployments/` 17 文件用途与 apply 顺序见 `07`「部署速查」。
- **运维与安全分组（09 / 10 / 11）**：三者是**三个独立关注点的 SSOT，刻意不合并**，仅交叉引用：
  - `09_可观测性与告警.md` = 指标 / 告警 / 故障排查单一来源；
  - `10_运维命令手册.md` = 密钥 / DB / Redis / Docker / 压测**命令速查**单一来源；
  - `11_安全与防护.md` = 安全**机制 / 参数 / 最佳实践**单一来源。
  - 视角互补、非重复示例：`09 §2.1` 的「限流/熔断**指标**」↔ `11 §四` 的「限流/熔断**机制**」；`10 §一` 的「CAPTCHA **密钥命令**」↔ `11 §二` 的「防水墙**验证机制**」。合并会塌缩关注点分离、破坏上述 SSOT。
- **可观测性**：`/metrics` 为指标权威，`09` 是指标清单 / 告警规则 / 故障排查的单一来源。
- **数据库迁移**：`migrations/` + `scripts/migrate.sh` 为权威，`06` 为机制说明（非 SQL 驱动域无需迁移）。
- **安全**：`11_安全与防护.md` 为安全专题单一来源（`01` / `02` / `03` / `04` / `05` / `09` 仅从各自视角引用或描述，机制/参数/最佳实践以 `11` 为准）。

> **护栏**：禁止将分组 SSOT 文档（`01`/`02`、`09`/`10`/`11`）盲目合并。它们按「基线 vs 权威」「观测 vs 命令 vs 安全」刻意分关注点，合并会丢失 SSOT 边界、诱发后续重复。如需收敛重复，优先做**交叉引用**（如「机制以 `11 §四` 为准」），而非合并文件。

## 术语表（Glossary）
- **L1 / L2 / L3**：三级缓存（进程内 Ristretto / Redis / 主存储）
- **SRS**：需求规格说明书（`02`）
- **SSOT**：Single Source of Truth，单一来源
- **PDB**：Pod Disruption Budget（pod 中断预算）
- **MGR**：MySQL Group Replication（MySQL 组复制）
- **CH**：ClickHouse（监控库）
- **ES**：Elasticsearch（日志/审计库）
- **MQ**：消息队列（Kafka）
- **HA**：High Availability（高可用）
- **JWT**：JSON Web Token（认证令牌）
- **CAPTCHA**：人机验证码（防水墙）
- **K8s**：Kubernetes
- **LB**：Load Balancer（负载均衡）
- **IOPS / QPS / TPS**：存储 IO 每秒 / 每秒查询数 / 每秒事务数
- **TTL**：Time To Live（生存时间）
- **ER**：Entity Relationship（实体关系）
- **HPA**：Horizontal Pod Autoscaler（水平 Pod 自动扩缩）
- **StatefulSet**：K8s 有状态工作负载（稳定网络标识/存储，承载扫描分片）
- **Ingress**：K8s 外部流量接入（域名/LB）
- **RBAC**：基于角色的访问控制
- **Pod**：K8s 最小调度单元
