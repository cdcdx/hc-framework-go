# 配置参考（config.yaml）

> 本文件是 `config/config.yaml` 的**完整字段参考手册**（单一来源）。所有字段以仓库内 `config/config.yaml` 为准；环境变量可覆盖任意字段，规则为 `APP_` + 下划线路径，如 `APP_SERVER_PORT=9090`、`APP_CACHE_L2_POOL_SIZE=500`。
> 加载优先级：**文件默认值 → 环境变量覆盖 → 远程配置中心（可选）**。
> 提交到仓库的 `config/config.yaml` 仅含开发默认值；**去密钥模板**见 `config/config.example.yaml`，含密钥字段（JWT 签名密钥、OAuth/Captcha Secret、SMTP 密码、各 DSN 密码）请通过环境变量或 K8s Secret 注入，勿明文提交（本地覆盖可用 `config/config.local.yaml`，已被 `.gitignore` 忽略）。
>
> 标注「🔥 热更新」的字段在运行时可通过 `SIGHUP` 信号、`POST /debug/reload` 或文件监听（Viper watch）即时生效，无需重启。

## 一、server — 服务配置

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `server.port` | int | `8080` | HTTP 监听端口 |
| `server.host` | string | `0.0.0.0` | 监听地址 |
| `server.mode` | string | `release` | `debug` / `release` / `test` |
| `server.read_timeout` | duration | `30s` | 读超时 |
| `server.read_header_timeout` | duration | `15s` | 读头超时（防御慢头攻击，独立于 write_timeout；0 回退 read_timeout） |
| `server.write_timeout` | duration | `30s` | 写超时 |
| `server.idle_timeout` | duration | `90s` | keep-alive 空闲连接存活时间（须明显大于心跳间隔 30s，否则连接被提前关闭导致 "server closed idle connection"/EOF） |
| `server.shutdown_timeout` | duration | `30s` | 优雅关闭等待时间 |
| `server.max_header_bytes` | int | `1048576` | 请求头最大字节数（默认 1MB；`<=0` 回退 net/http 默认 1MB）。防御超大/畸形请求头占用内存与慢头攻击 |
| `server.max_conns_per_ip` | int | `0` | 单 IP 最大并发连接数（`0`=不限）。连接级基础限流，防止单一客户端耗尽连接 |
| `server.max_conns` | int | `0` | 全局最大并发连接数（`0`=不限）。进程级连接耗尽防线：超限新连接被立即拒绝（连接级快速失败），保护后端资源不被连接风暴打垮（K8s 下仍依赖 readiness/HPA）。`internal/bootstrap/connlimit.go` |
| `server.concurrency_limit` | int | `0` | **应用层在途请求并发硬上限（`0`=关闭，默认不限）**。在「连接级上限」与「令牌桶限流」之后、业务处理器之前，对同时在途请求数再设进程级上限：达上限即快速失败 503（负载卸载/load shedding），避免无界 goroutine 在 DB/下游抖动时堆积压垮后端。容量按容量规划设定（≈ DB 连接池上限 / 单请求平均下游并发度），重启生效。`internal/middleware/concurrency.go` |
| `server.request_timeout` | duration | `10s` | 单请求处理上限：给每个请求 ctx 上 deadline，使下游 DB/锁等待有界，把连接池饱和时的「无限挂起」收敛为有界 504（`middleware.Timeout`） |
| `server.cors.allowed_origins` | []string | `["*"]` | 跨域允许来源 |
| `server.cors.allowed_methods` | []string | `GET/POST/PUT/DELETE/OPTIONS` | 允许方法 |
| `server.cors.allowed_headers` | []string | `Authorization`/`Content-Type`/`X-Trace-Id` | 允许头 |

## 四、mq — 消息队列

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `mq.type` | string | `memory` | `kafka`/`rabbitmq`/`rocketmq`/`memory`/`none`。事件总线完全由该字段驱动，切换类型无需改动其它代码。`memory` 为进程内总线，仅用于本地开发/测试，不持久化（at-most-once：无订阅者时消息丢弃）。**`none` / 未配置 / 连接项缺失时，工厂返回 no-op 生产者与消费者（非 nil，Send/Subscribe 为空操作）**，使「不启用事件总线」在接口层强制成立、调用方无需各自判空也不会 panic；下游仍按「无总线」正确分支运行：idle 结算 / 用户事件仅落库不发布、缓存写降级退化为本地异步写 L2、积分余额由进程内 Outbox 同步快路径 + 后台 relay 保证最终一致（详见 `13_代码优化记录.md`） |

| `mq.kafka.consumer.connection_warn_threshold` | int | `0` | **多连接开销告警阈值**（见 §6.5 #8）。每个 `(topic, partition)` 一个 Reader 一个 broker TCP 连接，分区多时连接数=分区数；reader 数超过该阈值时启动告警，提示合并分区或迁移消费组。`0`（默认）不告警 |
| `mq.kafka.consumer.lag_scrape_interval` | duration | `15s` | **消费 lag 可观测抓取间隔**（见 §6.5 / §3.59）。后台周期读取各 reader 的 `Stats().Lag` / `Stats().Offset`，经 `ConsumerMetrics` 暴露到 Prometheus（`mq_consumer_lag` / `mq_consumer_offset`），用于观测消费滞后。`0`（默认 15s）用默认；未启用 Prometheus 时为 no-op 不影响消费 |
| `mq.kafka.consumer.mode` | string | `direct` | **消费模式显式声明**（「配置收敛」，见 §6.5 / §3.60）。`direct`（默认）：无消费组 + 按分区直读，规避 kafka-go v0.4.51 与 Kafka 4.0 KRaft group coordinator 不兼容导致的 `-1 Unknown`。`group`：消费组模式——当前 kafka-go v0.4.51 在 KRaft 4.0 下不可用（coordinator 握手返回 `UNKNOWN_SERVER_ERROR(-1)` 且无法自愈），显式配置为 `group` 会启动报错（P0 待升级客户端）。空值回落 `direct`；未知值启动时告警并回落 `direct` |
| `mq.kafka.consumer.ordered_commit` | bool | `false` | 同分区顺序提交（**仅保证分区内**，不提供跨分区一致性）。`false`（默认）：worker 池并发处理 + offset「只增不减」推进、后台周期落盘（默认 5s），崩溃时该区间消息会被重放（at-least-once）。`true`：每分区串行「处理完一条即同步落盘 offset」，**分区内严格有序且把崩溃重放窗口缩到最小**，代价是单分区并发降为 1（跨分区仍并行，并发度=分区数）。对「分区内有序 + 最小重放窗口」要求高、可接受单分区串行时开启。真正的「恰好一次 + 跨分区幂等」需把相关事件路由到同一分区（相同 key），并注入 `ConsumerProgressStore`（如 `SQLProgressStore`，与业务库同实例）获得 event_id 跨分区去重（消费侧 Outbox） |

| `migration.enabled` | bool | `true` | 迁移总开关 |
| `migration.auto_migrate` | bool | `true` | 启动时自动迁移（**生产建议关，用 `make migrate`**） |
| `migration.path` | string | `./migrations` | 迁移目录 |
| `mail.enabled` | bool | `false` | 邮件开关（`false` 时跳过发信，注册不受影响） |
| `mail.site_name` | string | `HC Framework` | 邮件站点名 |
| `mail.smtp.host` / `port` | string/int | `smtp.example.com` / `465` | SMTP 服务器 |
| `mail.smtp.username` / `password` | string | `""` | 认证 |
| `mail.smtp.from` / `from_name` | string | `no-reply@example.com` | 发件人 |
| `mail.smtp.use_tls` | bool | `true` | 隐式 TLS（465） |
| `mail.smtp.insecure_skip_verify` | bool | `false` | 跳过 TLS 校验（仅内网自签） |

> 迁移机制详见 [06_数据库迁移.md](./06_数据库迁移.md)；完整部署配置见 [07_集群设备部署手册.md](./07_集群设备部署手册.md)。
