## 二、数据库命令

框架四个数据域可独立选择驱动，主库不可用时回退本地 SQLite（见 [06_数据库迁移.md](./06_数据库迁移.md)）：

| 数据域 | 首选驱动 | 备选 | 说明 |
|--------|----------|------|------|
| 业务 `business` | mysql / postgres / sqlite | sqlite | `migrations/business` 含 mysql/postgres/sqlite 完整迁移 |
| 用户 `user` | mongodb / sqlite | sqlite | `mongodb` 集合/索引运行时自管理，无迁移文件 |
| 日志 `log` | elasticsearch / sqlite | sqlite | `elasticsearch` 索引运行时自管理，无迁移文件 |
| 监控 `monitor` | clickhouse / sqlite | sqlite | `clickhouse` 有独立迁移文件 |

### 2.1 用户库 · MongoDB

```bash
# 进入容器
docker exec -it mongodb mongosh -u root -p 123456 --authenticationDatabase admin

# 库操作
db.createCollection("hc_users")            # 创建库
db.dropDatabase()                          # 删除库
use hc_users                               # 选择库

# 集合操作
show collections                           # 查看所有集合
db.users.deleteMany({})                    # 清空集合
db.users.drop()                            # 删除集合
db.users.renameCollection("old_users")     # 重命名集合
db.users.stats()                           # 集合统计
db.users.find().limit(10)                  # 查询前 10 条
db.users.count()                           # 统计数量

# 创建业务用户（读写权限）
db.createUser({
  user: "demo",
  pwd: "123456",
  roles: [{ role: "readWrite", db: "hc_users" }]
})
```

### 2.2 业务库 · MySQL

```bash
# 进入容器
docker exec -it mysql mysql -u root -p123456

# 建库
CREATE DATABASE IF NOT EXISTS hc_business CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
use hc_business;

# 授权
CREATE USER IF NOT EXISTS 'demo'@'%' IDENTIFIED BY '123456';
GRANT ALL PRIVILEGES ON hc_business.* TO 'demo'@'%';
FLUSH PRIVILEGES;
```

### 2.3 业务库 · PostgreSQL

```bash
# 进入容器
docker exec -it postgresql psql

# 建库
CREATE DATABASE hc_business ENCODING 'UTF8';
\c hc_business
```

### 2.4 日志库 · Elasticsearch

```bash
# 查看索引
curl http://localhost:9200/_cat/indices?v

# 查询审计日志
curl -X GET "http://localhost:9200/hc_logs-2026.07.08/_search?pretty" \
  -H 'Content-Type: application/json' \
  -d '{ "query": { "match_all": {} } }'
```

### 2.5 监控库 · ClickHouse

```bash
# 进入容器
docker exec -it clickhouse clickhouse-client --user admin --password 123456

# 建库与查询
CREATE DATABASE IF NOT EXISTS hc_monitor;
SHOW TABLES FROM hc_monitor;
DESCRIBE hc_monitor.monitor_metrics FORMAT PrettyCompact;
SELECT count() FROM hc_monitor.monitor_metrics;
SELECT * FROM hc_monitor.monitor_metrics ORDER BY created_at DESC LIMIT 20 FORMAT PrettyCompact;

# 创建管理员
CREATE USER admin IDENTIFIED BY '123456';
GRANT ALL ON *.* TO admin;
```

## 三、Redis 命令（挂机判活 / 缓存 / 选主诊断）

> 挂机心跳、活跃集合、布隆过滤器、选主租约、账号锁定均存储在 Redis。离线检测与容量排查常用如下命令。

```bash
# 进入容器
docker exec -it redis redis-cli

# —— 连接与内存 ——
INFO memory                 # 查看 used_memory_human / maxmemory
CONFIG GET maxmemory
CONFIG GET maxmemory-policy # 建议 allkeys-lru

# —— 健康检查 ——
PING
# 或经 HTTP：GET /health 查看 l2_ok 与 l2_latency_ms

# —— 挂机心跳 key（idle:hb:{user}:{device}，TTL=timeout_threshold）——
KEYS 'idle:hb:*'            # 在线设备数（生产慎用 KEYS，建议 SCAN）
SCAN 0 MATCH 'idle:hb:*' COUNT 1000
TTL idle:hb:u_1a2b:dev-0001

# —— 活跃集合分片（idle:active:set:{0..255}）——
SCARD idle:active:set:0    # 某分片活跃成员数
SMEMBERS idle:active:set:0 # 列出成员（调试用）

# —— 布隆过滤器 / 缓存命名空间 ——
KEYS 'cache:bloom'
KEYS 'hc:*'                # 受 cache.key_prefix 控制

# —— 选主租约 / 存活上报（多副本）——
TTL idle:leader            # Leader 租约剩余
KEYS 'idle:pod-alive:*'    # 各 Pod 存活上报

# —— 账号锁定（hash tag 保证单 slot）——
HGETALL '{login:fail:u_1a2b}'   # count + lock 字段

# —— 关闭保护模式（仅测试，重启失效）——
CONFIG SET protected-mode no
# 永久生效：
CONFIG SET protected-mode no
CONFIG REWRITE
```

> 容量评估：心跳 key ≈ 70~100B/会话，活跃集合成员 ≈ 40B；1M 在线约 100MB + 40MB（见 [08_Redis集群部署指南.md](./08_Redis集群部署指南.md)）。

## 四、Docker 命令

```bash
# Kafka 可视化管理
docker run -d --name kafka-map -p 8888:8080 \
  --restart always --network 1panel-network \
  -e DEFAULT_USERNAME=demo \
  -e DEFAULT_PASSWORD=123456 \
  -v /opt/data/kafka-map:/usr/local/kafka-map/data \
  dushixiang/kafka-map:latest

# 创建 MongoDB 业务用户
docker exec mongodb mongosh "mongodb://127.0.0.1:27017/admin" --quiet --eval '
  db.createUser({
    user: "demo",
    pwd: "123456",
    roles: [{ role: "readWrite", db: "hc_users" }]
  })
'

# 关闭 Redis 保护模式（重启失效）
docker exec redis redis-cli CONFIG SET protected-mode no
# 永久生效
docker exec redis redis-cli CONFIG SET protected-mode no
docker exec redis redis-cli CONFIG REWRITE
docker exec redis redis-cli CONFIG GET protected-mode
```

## 五、压力测试命令

### 5.1 安装 k6

```bash
# Linux (Debian/Ubuntu)
sudo gpg -k && sudo gpg --no-default-keyring --keyring /usr/share/keyrings/k6-archive-keyring.gpg \
  --keyserver hkp://keyserver.ubuntu.com:80 --recv-keys C5AD17C747E3415A3642D57D77C6C491D6AC1D69
echo "deb [signed-by=/usr/share/keyrings/k6-archive-keyring.gpg] https://dl.k6.io/deb stable main" \
  | sudo tee /etc/apt/sources.list.d/k6.list
sudo apt-get update && sudo apt-get install k6
```

### 5.2 运行场景

```bash
make k6-test          # 运行全部 4 个场景
make k6-test-auth     # 场景1：注册/登录（100 req/s，5min）
make k6-test-idle     # 场景2：挂机心跳（10000 VU，10min）
make k6-test-shop     # 场景3：兑换抢购（1000 VU，验证零超卖）
make k6-test-mixed    # 场景4：混合负载（2000 VU，70%读+30%写，30min）
```

### 5.3 自定义参数

```bash
# 指定目标服务器
k6 run --env BASE_URL=http://192.168.1.100:8080 scripts/k6/auth.js

# 指定兑换商品 ID
k6 run --env ITEM_ID=2 scripts/k6/shop.js

# 导出 JSON 结果
k6 run --out json=results.json scripts/k6/auth.js

# 输出到 Prometheus（需配置）
k6 run --out experimental-prometheus-rw scripts/k6/auth.js
```

### 5.4 压测前置准备

```bash
make run-sqlite     # 1) 确保服务运行

# 2) 场景3（兑换抢购）需预置库存：在 hc_business 创建商品 stock=500，并为测试用户预分配积分
# 3) 场景3 建议临时调高限流（config.yaml）：
#    ratelimit.per_user.rate: 10000
#    ratelimit.per_user.burst: 5000
#    压测完成后恢复原值
```
