# 安全与防护（Security & Hardening）

本文档是 HC Framework **安全专题的单一来源（SSOT）**，汇总分散在 [001_需求.md](./001_需求.md) / [002_需求规格说明书.md](./002_需求规格说明书.md) / [202_配置参考.md](./202_配置参考.md) 中的安全内容。认证链路、限流熔断、缓存防护等机制背景另见 [101_架构说明.md](./101_架构说明.md)、[201_API参考.md](./201_API参考.md)、[403_可观测性与告警.md](./403_可观测性与告警.md)。

## 一、认证与授权（JWT）

- **令牌**：Access Token（短时效，默认 2h）+ Refresh Token（长时效，默认 168h），`Authorization: Bearer <access_token>`。
- **黑名单**：登出/过期 Token 写入 Redis `jwt:blacklist:{jti}`，TTL 随 Token 剩余有效期；网关/中间件校验时查黑名单。
- **修改密码即失效**：`PUT /api/v1/user/password` 校验旧密码更新哈希，并将 `pwd_change:{user_id}` 写入黑名单，使该用户**所有已签发 Token 立即失效**。
- **Refresh 轮转**：刷新时使旧 refresh `jti` 失效，降低重放风险。
- **路由鉴权**：业务路由串 `Auth` 中间件做 JWT 校验 + Token 验证 + 黑名单检查（见 [101_架构说明.md](./101_架构说明.md) 中间件链）。

## 二、人机验证（防水墙 / CAPTCHA）

- 多厂商可插拔：腾讯云验证码 / Cloudflare Turnstile / reCAPTCHA / hCAPTCHA，由 `captcha` 决策引擎（`pkg/captcha`）按风险选择挑战。
- 触发点：注册、登录等认证接口叠加 `Captcha` 中间件（见 [101_架构说明.md](./101_架构说明.md)）。
- 配置见 [202_配置参考.md](./202_配置参考.md)。

## 三、账号防护

- **IP 限流**：注册/登录按 IP 限流（`security.ip_limit`），防批量撞库。
- **账号锁定**：连续失败计数 + 锁定（`security.account_lock`）；锁定状态经 `AccountLockStore` 跨 Pod 共享（Redis 实现，L2 不可用时回退进程内计数）。
- **失败递增等待**：`security.login_fail_delays` 梯度延长重试间隔，抑制暴力破解。
- 相关实现：`internal/service/auth/account_lock.go`、`internal/middleware/security.go`。

## 四、限流与熔断

- **限流**：令牌桶（`internal/middleware/ratelimit.go`），支持 `global` 与 `per_user`；心跳等高频路径经 `ratelimit.exempt_paths` 豁免（避免 429 误判离线）。
- **熔断**：`sony/gobreaker` 三态熔断（Closed/Half-Open/Open），按路由分组；触发后全局读降级（`cache.degrade.read_skip_l2`）。
- **热更新**：限流/熔断/安全 IP 限流/账号锁定参数支持运行时热更新（见 [202_配置参考.md](./202_配置参考.md)）。
- 指标：`rate_limit_total`、`circuit_breaker_state` （见 [403_可观测性与告警.md](./403_可观测性与告警.md)）。

## 五、数据安全

- **密码哈希**：bcrypt（`pkg/bcrypt`），存储 `password_hash`，不落明文。
- **密码传输规范**：注册/登录的 `password` 字段接收 **SHA256 哈希后的 64 位十六进制串**，客户端先 `sha256(password)` 再提交，防止明文在网络中泄露。
- **请求日志脱敏**：`RequestLogger` 对敏感字段脱敏为 `***`；`/login`、`/register` **不记录 body**；写请求体超过 4KB 截断。
- **审计日志**：同步 `LogService` 写 `audit_logs`（注册/登录/设备上线/任务/兑换）。

## 六、密钥与配置安全

- **密钥注入**：JWT `signing_key`、DB 密码、第三方 API Key 经 K8s Secret 注入（见 [401_集群设备部署手册.md](./401_集群设备部署手册.md)），不落明文到 `config.yaml`。
- **敏感配置**：`secret.yaml` 管理与挂载；`config.yaml` 仅保留非敏感默认值。
- **热更新安全开关**：缓存降级、限流/熔断阈值等可在不重启情况下调整（[202_配置参考.md](./202_配置参考.md)）。

## 七、网络安全（NetworkPolicy）

- `deployments/networkpolicy.yaml` 限定 Pod 间与对外部访问的端口/来源，配合 Ingress/Nginx 接入层 TLS 卸载与前置限流。
- 完整规则矩阵见 [401_集群设备部署手册.md](./401_集群设备部署手册.md)。

## 九、最佳实践

1. 生产环境务必通过 K8s Secret 注入密钥，禁止提交明文 `config.yaml`。
2. 公网暴露的认证接口开启 CAPTCHA + IP 限流 + 账号锁定组合。
3. 心跳等高频内部路径加入 `ratelimit.exempt_paths`，避免误熔断/误限流。
4. 修改密码/登出后依赖黑名单使旧 Token 失效，前端应清除本地令牌。
5. 安全相关参数（限流/熔断/账号锁定）变更优先走热更新，避免重启影响在线设备。
