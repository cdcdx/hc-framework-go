# 903 · API 参考（go-zero 版）

> 本文档对应 `app/gateway/api/gateway.api` 与 `app/rpc/hc.proto` 的真实定义。
> 路由契约与 gin 版保持一致（路径/字段不变），但底层改为 rest 网关 + 单一 rpc。

---

## 1. 统一响应格式

所有响应均为：

```json
{ "code": 0, "message": "success", "data": {}, "trace_id": "..." }
```

- `code`：业务码（0 成功，非 0 见错误码表）
- `message`：中文提示
- `data`：业务数据（`null` 表示无）
- `trace_id`：请求链路 ID（go-zero 自动生成，便于排查）

分页接口额外结构：

```json
{ "code": 0, "message": "success", "data": { "items": [], "next_cursor": "0", "has_more": false }, "trace_id": "..." }
```

## 2. 中间件分组

| 组 | 路由前缀 | 中间件 |
|----|----------|--------|
| 公开 | `/health` `/ready` `/api/v1/captcha/config` `/api/v1/auth/refresh` | 无 |
| 防水墙 | `/api/v1/auth/register` `/api/v1/auth/login` | `SecurityIPLimit` → `Captcha` |
| OAuth | `/api/v1/auth/google` | 无验证码 |
| 鉴权 | 其余全部业务路由 | `JwtAuth`（校验 JWT，注入 `user_id` 到 context） |

> `SecurityIPLimit` 为网关内存滑动窗口限频（配置见 [902_配置参考.md](902_配置参考.md)），超限返回 429。
> `Captcha` 校验请求头 `X-Captcha-Token`（由 `/api/v1/captcha/config` 下发）。

## 4. 核心数据结构

> 与 `hc.proto` 消息一一对应，JSON 字段名以 gateway 侧 `types` 为准（nake→camel）。

### User (`UserInfo`)
```
user_id, username, email, avatar_url, points_balance, status, created_at
```

### IdleRecord（挂机会话）
```
id, user_id, device_id, start_time, end_time, duration_seconds,
points_earned, status(active|completed|timeout), last_heartbeat_at
```

### TaskInfo（任务）
```
id, task_type(daily|weekly|achievement), task_key, task_name, target_value,
reward_points, is_active, current_progress, is_completed, is_claimed, period
```

### ItemInfo（商品）
```
id, name, description, price_points, stock, image_url, category, is_active,
sales_status(offline|on_sale|sold_out)
```

### OrderInfo（订单）
```
id, user_id, item_id, item_name, points_spent, order_status(pending|completed|cancelled),
activity_id(0=普通兑换), created_at
```

### FlashActivityInfo（抢购活动）
```
id, item_id, name, start_time, end_time, limit_qty, sold_qty,
per_user_limit, price_points, status(active|ended|pending),
sales_status(presale|on_sale|sold_out|ended)
```

## 5. 业务规则要点（与代码一致）

- **挂机结算**：`heartbeat` 超过 5 分钟未续命 → 结算为 `timeout` 并需重新 `start`；`stop` / `stop-device` 即时结算。结算积分写入 `idle_daily_points`（按天累计）并通过进程内 `AddPoints` 入账。
- **活跃设备上限**：`Config.Idle.MaxActiveDevices`（默认 1），超过报 `maximum active devices reached`（`CodeUnknownError` 文案）。
- **任务进度**：由 `ReportProgress(task_key, delta)` 在登录/挂机结算/兑换完成时事件驱动累加（进程内调用）。
- **领取**：任务 `is_completed` 且未 `is_claimed` 才可领，奖励经 `AddPoints` 入账。
- **商城兑换**：`DeductPoints`（余额不足 → `CodePointsInsufficient`）→ 扣库存 → 建单（单事务）。
- **抢购**：活动未开始/已结束/已售罄/超每人限购 → 直接拒绝；限量内 `sold_qty+1` 入库，并发靠事务行锁保护。

## 7. RPC 服务方法（`hc.proto` `service Hc`）

共 24 个方法，按域前缀划分，供网关 logic 通过 `svcCtx.HcRpc.*` 调用：

**user 域（认证/用户/积分）**
`Register` `Login` `GoogleOAuth` `RefreshToken` `ChangePassword` `GetProfile` `UpdateProfile` `GetPoints` `AddPoints` `DeductPoints`

**idle 域（挂机）**
`IdleStart` `IdleHeartbeat` `IdleStop` `IdleStopDevice` `IdleStatus` `IdleRecords`

**task 域（任务）**
`TaskList` `TaskProgress` `TaskClaim` `ReportProgress`

**shop 域（商城/抢购）**
`ShopItems` `ShopRedeem` `ShopOrders` `ShopOrderDetail` `FlashActivities` `FlashRedeem`
