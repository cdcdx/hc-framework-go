## 一、已实现能力（✅）

### 1. 三级缓存（L1 + L2 + 策略引擎）
- **L1**：Ristretto 本地内存缓存，LFU + Window-TinyLFU 回收，命中率/容量/驱逐指标可查。
- **L2**：Redis / Valkey 封装，支持单机 / Sentinel / Cluster、连接池、Pipeline、Pub/Sub 自动重连。
- **策略引擎**（`internal/cache/strategy.go`）：L1 → L2 → 回源三级读取；延迟双删（立即删 L1+L2 + 异步二次删 L1，延迟取 `max(DoubleDeleteDelay, ReplicationLag×2)`）；Pub/Sub 广播失效各 Pod 本地 L1。

### 2. 缓存防护
- **穿透**：Redis Bitmap 布隆过滤器 + 空值缓存（TTL 60s）。
- **击穿**：热点 Key 回源加 Redis `SETNX` 分布式锁，随机 token + Lua 脚本校验防误解锁；未获取锁的协程自旋等待（最多 10 次 × 50ms，且监听请求 `ctx.Done` 及时退出）。
- **雪崩**：TTL 随机偏移（`ttl_jitter`）。

### 3. 数据库与读写分离
- 多驱动适配器：SQLite / MySQL / PostgreSQL（GORM）、MongoDB、ClickHouse、Elasticsearch。
- 读写分离（`internal/db/rw_db.go`）：主库写 / 事务，从库读 round-robin；从库 3s 间隔 `Ping`，不健康自动摘除并降级主库；主从复制延迟感知双删。
- 业务 Repository 集成缓存：读路径走三级缓存，写路径精确失效（按 `domain:entity:id` 维度）。

### 4. 安全与治理
- JWT 鉴权 + Redis 黑名单（`jwt:blacklist:{jti}`，TTL 随 Token 剩余有效期）。
- 令牌桶限流（全局）；sony/gobreaker 三态熔断（按路由分组，HALF_OPEN 探测）。
- 验证码防水墙：腾讯 / Turnstile / reCAPTCHA / hCAPTCHA 可插拔 + 决策引擎（滑动窗口 + 白名单）。
- 商城兑换乐观锁库存（`WHERE version=?`），杜绝超卖；并发兑换额外用分布式锁 `redeem:lock:{user_id}` 串行化（锁失效由乐观锁兜底，未启用缓存时降级为仅乐观锁）。
- **账号安全**（消费 `security` 配置段，需求 §8）：
  - IP 级限流：`/register`、`/login` 按 IP 滑动窗口限流（`security.ip_limit.register_per_minute=3` / `login_per_minute=10`），超限返回 429（`middleware.SecurityIPLimit`）。
  - 连续失败锁定：单账号连续失败达 `security.account_lock.max_failures`（默认 5）锁定 `lock_duration`（默认 15m）；登录失败按 `security.login_fail_delays`（默认 `[0,0,5,5,30]`）递增等待。
  - Refresh Token 轮转失效：每次 `/auth/refresh` 将旧 refresh `jti` 写入黑名单（TTL=剩余有效期），旧 refresh 立即失效，防止 7d 内重放。
  - 修改密码接口 `PUT /api/v1/user/password`：校验旧密码 → 更新哈希 → 将 `pwd_change:{user_id}` 写入黑名单，使所有已签发 Token 立即失效（auth 中间件逐请求校验）。
  - 用户事件发布：注册/登录成功发布 `user.registered` / `user.logged_in` 事件到 `user-events`（Kafka 启用时；`mq.type != kafka` 时自动跳过）。

### 5. 可观测性（部分）
- Zap 结构化 JSON 日志 + 日志级别热更新（`/debug/loglevel`）。
- **请求日志脱敏**（需求 §3）：`RequestLogger` 对请求体中的敏感字段（password/token/secret/authorization 等，取自 `logging.sensitive_fields`）脱敏为 `***`；敏感路径（`/login`、`/register`）不记录请求体；其它写请求体超过 `logging.request_body_max_size`（默认 4KB）截断。
- `/health` 返回缓存健康与延迟；`/metrics` 返回真实缓存统计（JSON）。
- 链路追踪（OpenTelemetry 兼容）：`Trace` 中间件创建 server span 并透传 W3C `traceparent`（兼容旧 `X-Trace-Id`）；业务服务可经 `trace.Start(ctx, name)` 开启子 span（见 `shop_service.Redeem`、`idle_service.Start`）；默认 `LogExporter` 写入 Zap 结构化日志（含 `trace_id`/`span_id`/`parent_id`/`duration_ms`/`status`/`error`）。配置 `exporter: otlp` 时，`OTLPHTTPExporter` 以 OTLP/HTTP JSON 批量 POST 到 `:4318/v1/traces`（零新增依赖，对接 Tempo/Jaeger），内部以「有缓冲 channel + 后台 worker 批量 flush」发送，优雅关闭时 flush 残余 span。

### 6. 配置热更新与读写降级（需求 §9 / §11）
- **配置热更新**：`config.Manager` 以 `atomic.Pointer` 持有不可变 `*Config`，`Reload()` 重新解析 YAML 并原子替换指针；各组件在请求路径上经 `Get()` 读取，无锁、无数据竞争。触发方式：① 文件监听（Viper `OnConfigChange`，编辑器保存即重载）；② `SIGHUP` 信号（`Manager.Watch`）；③ HTTP API `POST /debug/reload`（返回 `version`）。
  - 已接入实时生效的参数：**限流参数**（令牌桶 rate/burst/白名单）、**熔断阈值**（failure_threshold/open_duration 等）、**安全 IP 限流阈值**、**账号锁定/递增等待**、**缓存读写降级开关**。非连接级配置（DB 连接串、JWT 密钥等）仍取启动快照，运行时变更需重启（安全考量）。
- **读降级**：`cache.degrade.read_skip_l2=true`（或熔断触发全局降级）时，`CacheStrategy.Get` 跳过 L2（Redis）与布隆过滤器，直读 DB（仍回填 L1），缓解 Redis 压力（需求 §11）。
- **写降级**：`cache.degrade.write_async=true`（或熔断触发全局降级）时，`CacheStrategy.Set` 跳过同步 L2 写，转异步：Kafka 可用时投递 `cache.invalidate` 事件到 `cache_events` 主题（由消费者异步刷新缓存）；无 Kafka 时退化为本地异步 goroutine 写 L2。
- **熔断联动降级**：熔断器（按路由分组）打开时经 `internal/degrade` 置位全局降级（多熔断器计数，互不影响），关闭时自动解除；缓存策略引擎据此强制 read/write 全量降级。
- **读降级回填语义**：读降级或全局降级（熔断）时，`CacheStrategy.Get` 回源后回填缓存**只写 L1、不写 L2**（`loadAndFill`/`fillCache`/`safeSetNull` 的 `fillL2`/`writeL2` 参数；`fillCache` 刻意同步写 L2 以保分布式锁单飞语义），避免继续打扰 Redis，与「跳过 L2」目的一致；正常路径仍回填 L1+L2。
- **热更新健壮性**：`config.LoadManager` 与 `Reload` 替换生效配置前调用 `Config.Validate`；校验失败（如 `server.port` 越界、`server.mode` 为空）时 `Reload` **保留旧配置不替换**并返回错误，启动加载则直接报错退出，避免热更新把服务搞崩。
- **配置热更新数据竞争修复**：`viper` v1.19 的 `WatchConfig` 监听 goroutine 在文件变更时会先自行 `ReadInConfig()` 刷新被监听的 `v`，再回调 `OnConfigChange`；原 `Reload()` 也对同一 `v` 调 `ReadInConfig()`，与监听 goroutine / SIGHUP / 另一次文件事件并发竞争同一可变状态（DATA RACE）。改为 `Reload()` 每次用**独立的新 viper 实例**从磁盘重新解析（复用 `loadFromFile`），与监听 goroutine 操作不同对象，竞争彻底消除，且重载重新读盘更符合预期。
- **热点 Key 检测无锁化（热路径性能）**：原 `HotKeyDetector.Record` 每次缓存访问抢全局 `sync.Mutex`，且 `IsHot`/`GetHotKeys` 每次全量扫描整个环形缓冲（最多 `windowSeconds×10000` 条）并在同锁下做选择排序——在单请求读路径上 `IsHot` 被调用 3 次，放大成多次百万级扫描 + 全局锁。重写为「按秒分桶（`sync.Map` + 原子计数）」：
  - `Record` 仅对所属秒桶计数器做原子累加，**零全局锁**；
  - `IsHot`/`GetHotKeys` 缓存 TopN 快照集，仅在 200ms 节流间隔后按需重算（排序 `O(n log n)` 但低频），查询 **O(1)**；
  - 每个秒桶轮转时整体换新 `sync.Map`，旧桶被 GC 回收，**内存有界**。
- **L1 命中计数无锁化**：`RistrettoCache` 的 `hitCount`/`missCount` 原在每次 `Get`/`GetMulti` 抢 `sync.RWMutex`，高并发下争用严重；改为 `atomic.Uint64`，热路径不再加锁。

### 7. 注册确认邮件（`pkg/mail`，需求 §3.1.4）
- `mail.enabled=true` 时，`AuthService.sendRegisterConfirmation` 在注册成功（含 Google OAuth 新账号）后异步发送 HTML 确认信（best-effort：独立 goroutine + 独立 background ctx，失败仅告警日志，不阻塞注册与 JWT 签发）；`mail.enabled=false`（默认）时 `mailer=nil` 直接跳过，注册流程不受影响。
- 基于标准库 `net/smtp` 实现 `SMTPSender`，无第三方依赖；支持隐式 TLS(465) / STARTTLS(587) / 明文(25)，可跳过自签证书校验（仅测试/内网）。HTML 模板由 `mail.BuildConfirmRegisterHTML` 渲染。
