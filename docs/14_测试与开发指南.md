# 测试与开发指南（Testing & Development Guide）

本文档从根 `README.md` 下沉并扩展，汇总**本地开发、测试与贡献流程**。开发规范与交付物见 [01_需求.md](./01_需求.md) / [02_需求规格说明书.md](./02_需求规格说明书.md)；接口契约见 [04_API参考.md](./04_API参考.md)；配置见 [05_配置参考.md](./05_配置参考.md)。

## 一、开发环境

- Go ≥ 1.25
- （可选）Redis 7.x / Valkey 8.x、MySQL 8.x / PostgreSQL 16.x
- **零依赖启动**：`make run` 以 SQLite 直接运行，无需任何中间件。

常用 `make` 命令：

```bash
make build        # 编译
make run          # 运行
make test         # 测试（go test -race ./...）
make test-idle    # 仅跑挂机相关用例
make lint         # golangci-lint 代码检查
make docker-build # Docker 构建
make clean        # 清理构建产物
```

## 二、代码规范

- 遵循 Go 官方 [Code Review Comments](https://github.com/golang/go/wiki/CodeReviewComments)，本地 `make lint`（依赖 [golangci-lint](https://golangci-lint.run/)）。
- **接口优先**：所有 Service / Repository 按接口设计，依赖通过构造函数注入。
- **三层架构**：`Handler → Service → Repository`。
- **API 注解**：接口添加 Swagger 注解，`swag init` 生成 `swagger/`。

## 三、添加一个新功能

1. 在 `internal/model/` 定义数据模型。
2. 在 `internal/repository/` 实现数据访问。
3. 在 `internal/service/` 实现业务逻辑。
4. 在 `internal/handler/` 实现 HTTP 处理器。
5. 在 `internal/router/` 注册路由。
6. 添加 Swagger 注解与必要的单元测试。

## 四、Git 工作流

```
feature/* → PR → Code Review → squash merge → main
```

## 五、测试

框架已实现较完整的单元/集成测试，全部经 `make test`（`go test -race ./...`，含 `-race` 数据竞争检测）。

### 测试覆盖（挂机、心跳批量落库与 Prometheus 指标）

| 测试文件 | 覆盖点 | 关键用例 |
|----------|--------|----------|
| `internal/service/idle/idle_eventdriven_test.go` | 事件驱动启停决策 + 结算 | Redis 不可用/配置关闭/集群自动禁用/正常订阅；结算三分支（清理悬挂 / 宽限重触 / 超时）+ 非法 key 早返回 |
| `internal/service/idle/idle_scanstop_test.go` | 轮询 scanner + 主动结算 | Redis 判活（离线结算 / 在线跳过）+ DB 降级 scanner；`Stop` / `StopDevice`（含 `ErrNotIdle` 边界） |
| `internal/service/idle/heartbeat_flusher_test.go` | 心跳聚合器 | 聚合去重 + 批量 `UPDATE`；已结算会话跳过；ticker flush + `Stop` 排空 |
| `internal/service/idle/idle_flush_fallback_test.go` | **降级路径（Redis 不可用）下批量落库仍生效** | 高频心跳不逐次写 DB、按需 flush 落库；未启用时保持旧逐次 UPDATE 兜底 |
| `internal/metrics/metrics_test.go` | Prometheus 指标暴露 + 缓存 Collector | `/metrics` 输出 Prometheus 文本格式并含 HTTP/限流/熔断埋点；缓存 Collector 输出 `cache_l1_*`/`cache_l2_enabled` 等指标 |
| `internal/middleware/metrics_test.go` | HTTP 指标中间件集成测试 | `http_requests_total` 按 method/path/status 累积；`/metrics` 暴露 `http_request_duration_seconds` |
| `internal/middleware/ratelimit_test.go` | 限流中间件集成测试 | 全局令牌桶耗尽返回 429，`rate_limit_total{rejected}` 递增 |
| `internal/middleware/circuitbreaker_test.go` | 熔断中间件集成测试 | 持续 500 触发熔断打开，后续 503，`circuit_breaker_state=2` |
| `internal/router/router_test.go` | 路由集成测试（系统端点） | `/health`、`/ready`、`/metrics`、`/metrics/cache`、`POST /debug/reload` 均按预期返回 |

## 六、CI

CI 已增加非阻塞的 `golangci-lint` 步骤（`.github/workflows/ci.yml`），配置见 `.golangci.yml`。待存量问题清理完毕后，可移除 CI 步骤上的 `continue-on-error: true` 使其变为强制门禁。

## 七、本地调试

- **配置热更新**：`POST /debug/reload` 触发重载（文件监听 / `SIGHUP` 亦可）。
- **日志级别**：`PUT /debug/loglevel` 动态调整日志级别（AtomicLevel 热更新）。
- **指标自查**：`GET /metrics`（Prometheus 格式）、`GET /metrics/cache`（缓存统计 JSON）。
- **排查**：故障决策树与诊断命令见 [09_可观测性与告警.md](./09_可观测性与告警.md)、[10_运维命令手册.md](./10_运维命令手册.md)。
