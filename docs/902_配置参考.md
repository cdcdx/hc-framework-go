# 902 · 配置参考（go-zero 版 · 合并单进程部署）

本文档对应真实的 `config/server.yaml`（合并部署单一配置文件）。

---

## 1. 合并配置总览（`config/server.yaml`）

合并部署使用**单一配置文件**，含两个顶层块：

- `Gateway:` —— 网关配置（REST 入口 + Auth / Captcha / Security / Log / Middlewares）
- `Rpc:` —— 后端配置（Databases / Cache / MQ / JWT / 业务参数 / Log / Telemetry）

```yaml
# ===== 网关 (REST :8080) =====
Gateway:
  Name: hc-gateway
  Host: 0.0.0.0
  Port: 8080

  # JWT 校验配置（与 Rpc 签发共用同一套密钥/算法/issuer）
  Auth:
    Jwt:
      Algorithm: HS256
      SigningKey: "<32+ 字节随机密钥>"
      Issuer: hc-framework
      AccessTTL: 2h
      RefreshTTL: 168h

  # 验证码防水墙（false 时跳过校验）
  Captcha:
    Enabled: false
    Provider: none            # none / turnstile / recaptcha / hcaptcha / tencent
    SiteKey: ""
    SecretKey: ""
    AppID: ""

  # IP 限频（进程内窗口，单实例有效）
  Security:
    IPLimitEnabled: false
    IPLimitPerMinute: 30

  # 日志（go-zero logx）
  Log:
    ServiceName: hc-gateway
    Mode: console             # console / file / volume
    Encoding: plain           # json / plain
    TimeFormat: "2006-01-02T15:04:05.000"
    Level: info               # info / debug / warn / error
    Path: logs
    Rotation: size            # size / time
    KeepDays: 7
    MaxSize: 256
    Compress: false

  # 中间件开关
  Middlewares:
    Prometheus: true
    Log: true
    Recover: true
    MaxConns: true
    Breaker: false
    Shedding: false
    Timeout: true

# ===== Rpc 后端（同进程，不再暴露 gRPC）=====
Rpc:
  Name: hc.rpc

  # 多库配置（详见 §2.2.1）
  Databases:
    business:
      Driver: sqlite
      Dsn: file:./data/hc_business.db?cache=shared&_journal_mode=WAL
      MaxOpenConns: 10
      MaxIdleConns: 5
      ConnMaxLifetime: 1h
      PoolLabel: business
    # user / monitor / log 库同理...

  # 缓存（详见 §2.2.2）
  Cache:
    Enabled: false
    L1:
      Enabled: false
      MaxMemoryMB: 256
      DefaultTTL: 5m
    L2:
      Enabled: false
      Type: redis
      Addresses: ["127.0.0.1:6379"]
      Username: ""
      Password: ""
      DB: 0
      PoolSize: 200
      DialTimeout: 5s
      ReadTimeout: 3s
      WriteTimeout: 3s
      TLS: false
    Bloom:
      ExpectedKeys: 1000000
      FalsePositiveRate: 0.01

  # 消息队列（详见 §2.2.3）
  MQ:
    Enabled: false
    Type: memory
    # Kafka 专用（完全独立）
    Kafka:
      Brokers:
        - "127.0.0.1:9092"
      ConsumerGroup: hc-framework
      Topic: hc.events
      RequiredAcks: 1
      BatchSize: 100
      BatchBytes: 1048576
    # RocketMQ 专用（完全独立）
    RocketMQ:
      NameServer:
        - "127.0.0.1:9876"
      Group: hc-framework
      Retry: 3
      Topic: hc.events
      AccessKey: ""
      SecretKey: ""
      Namespace: ""
    # RabbitMQ 专用（完全独立）
    RabbitMQ:
      URL: "amqp://guest:guest@127.0.0.1:5672/"
      Exchange: hc.events
      ExchangeType: topic
      Queue: ""
      RoutingKey: hc.events
      Topic: hc.events
      Prefetch: 1
    # Memory 专用（完全独立）
    Memory:
      BufferSize: 1024

  # JWT 签发（与网关校验共用同一套密钥/算法/issuer，保证 token 互通）
  Jwt:
    Algorithm: HS256
    SigningKey: "<32+ 字节随机密钥>"
    Issuer: hc-framework
    AccessTTL: 2h
    RefreshTTL: 168h
    PrivateKeyPath: ""       # RS256 时使用
    PublicKeyPath: ""

  # 密码哈希成本（0=默认12；压测建议4-6，生产12+）
  BcryptCost: 4

  # Google OAuth（未配置时 /auth/google 返回第三方服务未配置错误）
  GoogleOAuth:
    ClientID: ""
    ClientSecret: ""
    RedirectURI: "http://localhost:8080/api/v1/auth/google"

  # 挂机业务参数
  Idle:
    MaxActiveDevices: 3
    PointsPerMinute: 10
    DailyPointsLimit: 14400
    TimeoutMinutes: 5
    ScanInterval: 30s

  # 秒杀业务参数
  FlashSale:
    Timeout: 3s

  # 日志（go-zero logx）
  Log:
    ServiceName: hc-rpc
    Mode: console
    Encoding: plain
    TimeFormat: "2006-01-02T15:04:05.000"
    Level: info
    Path: logs
    Rotation: size
    KeepDays: 7
    MaxSize: 256
    Compress: false

  # 链路追踪
  Telemetry:
    Name: hc.rpc
```

## 2. 字段说明

### 2.1 Gateway 块

| 字段 | 类型 | 默认/示例 | 说明 |
|------|------|-----------|------|
| `Gateway.Name` | string | `hc-gateway` | 服务名 |
| `Gateway.Host` / `Port` | string/int | `0.0.0.0` / 8080 | HTTP REST 入口 |
| `Gateway.Auth.Jwt.*` | — | — | JWT 校验参数，**必须与 Rpc.Jwt 对称** |
| `Gateway.Captcha.Enabled` | bool | false | false 跳过验证码校验 |
| `Gateway.Captcha.Provider` | string | `none` | 验证码 Provider 类型 |
| `Gateway.Security.IPLimitEnabled` | bool | false | IP 限频开关 |
| `Gateway.Security.IPLimitPerMinute` | int | 30 | 单 IP 每分钟最大请求数 |
| `Gateway.Log.*` | — | — | 日志（go-zero logx），见上方注释 |
| `Gateway.Middlewares.*` | bool | — | 中间件开关（Prometheus/Log/Recover/MaxConns/Breaker/Shedding/Timeout） |

### 2.2 Rpc 块

| 字段 | 类型 | 默认/示例 | 说明 |
|------|------|-----------|------|
| `Rpc.Name` | string | `hc.rpc` | 服务名 |
| `Rpc.Databases` | map | — | 多库配置（详见 §2.2.1） |
| `Rpc.DB` | — | — | 旧版单库配置（向后兼容，Databases 非空时忽略） |
| `Rpc.Cache` | — | — | 两级缓存配置（详见 §2.2.2） |
| `Rpc.MQ` | — | — | 消息队列配置（详见 §2.2.3） |
| `Rpc.Jwt.*` | — | — | JWT 签发参数，**必须与 Gateway.Auth.Jwt 对称** |
| `Rpc.Jwt.PrivateKeyPath/PublicKeyPath` | string | `""` | RS256 时填写 |
| `Rpc.BcryptCost` | int | 4（压测）/12（生产） | 密码哈希成本 |
| `Rpc.GoogleOAuth.*` | — | — | Google OAuth 凭据 |
| `Rpc.Idle.MaxActiveDevices` | int | 3 | 单用户最大活跃设备数 |
| `Rpc.Idle.PointsPerMinute` | int | 10 | 挂机每分钟积分 |
| `Rpc.Idle.DailyPointsLimit` | int64 | 14400 | 每日挂机积分上限 |
| `Rpc.Idle.TimeoutMinutes` | int | 5 | 挂机超时分钟数 |
| `Rpc.Idle.ScanInterval` | duration | 30s | 挂机状态扫描间隔 |
| `Rpc.FlashSale.Timeout` | duration | 3s | 秒杀事务超时 |
| `Rpc.Telemetry.Name` | string | `hc.rpc` | 链路追踪服务名 |
| `Rpc.Log.*` | — | — | 日志（go-zero logx） |

#### 2.2.1 `Rpc.Databases` — 多库模式

配置该块后走多库工厂 `dbclient.Factory`，与单库 `Rpc.DB` 二选一。

**四个库及其允许驱动（三选一）**：

| 库名 | 允许驱动 | 用途 |
|------|----------|------|
| `business` | postgres / mysql / sqlite | 业务主库，所有域共用 |
| `user` | mongodb / mysql / sqlite | 用户库（待按域拆分） |
| `monitor` | clickhouse / mysql / sqlite | 监控库（待按域拆分） |
| `log` | elasticsearch / mysql / sqlite | 日志库（待按域拆分） |

**通用字段**：

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `Driver` | string | — | 数据库驱动（从上述允许列表中选一） |
| `Dsn` | string | — | 通用连接串（vendor 段缺省时的回退值） |
| `MaxOpenConns` | int | 20 | 连接池上限（与 gormx 兜底对齐） |
| `MaxIdleConns` | int | 10 | 空闲连接数 |
| `ConnMaxLifetime` | duration | 1h | 连接最大存活时间 |
| `PoolLabel` | string | — | `db_pool_*` 指标的 `db` 标签，缺省取库名 |

**Vendor 段**（对标 gin 版 `database.<name>.<vendor>`）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `Mysql.Master` | string | MySQL 主库 DSN，优先于顶层 `Dsn` |
| `Mysql.MaxOpenConns` 等 | — | 覆盖顶层连接池（>0 生效，各字段独立） |
| `Postgres.Master` | string | PostgreSQL 主库 DSN，优先于顶层 `Dsn` |
| `Postgres.MaxOpenConns` 等 | — | 覆盖顶层连接池（>0 生效，各字段独立） |
| `Mongodb.Dsn` | string | MongoDB 连接串，优先于顶层 `Dsn` |
| `Clickhouse.Dsn` | string | ClickHouse 连接串，优先于顶层 `Dsn` |
| `Elasticsearch.Addresses` | []string | ES 地址列表 |
| `Elasticsearch.Username` / `Password` | string | ES 认证凭据 |
| `Elasticsearch.IndexPrefix` | string | ES 索引前缀，默认 `hc_logs` |

> **连接池解析优先级**（在 `Databases.ToSpecs()` 中完成）：
> 1. mysql/postgres：vendor 段 `MaxOpenConns>0` 覆盖顶层 open，`MaxIdleConns>0` 覆盖顶层 idle，`ConnMaxLifetime>0` 覆盖顶层 lifetime（三者独立，互不影响）。
> 2. sqlite/mongodb/clickhouse/elasticsearch：只用顶层值，vendor 段连接池字段被忽略。
> 3. 最终值经 `gormx.OpenWithPool` 再次兜底：mysql/postgres 未配置时兜底 20/10，sqlite 不限。单库硬上限 `hardMaxOpenConns=100`。
> 4. 解析失败的库只跳过并打 error 日志，不影响其余库装配。

#### 2.2.2 `Rpc.Cache` — 多级缓存

支持 L1（进程内 Ristretto）+ L2（redis/valkey 二选一）+ Bloom 穿透保护。

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `Rpc.Cache.Enabled` | bool | `false` | 缓存总开关（须显式开启） |
| `Rpc.Cache.L1.Enabled` | bool | `true` | L1 进程内缓存开关 |
| `Rpc.Cache.L1.MaxMemoryMB` | int | 256 | L1 内存上限（MB）；`MaxCost` 未配时自动换算为字节 |
| `Rpc.Cache.L1.DefaultTTL` | duration | `5m` | L1 默认 TTL |
| `Rpc.Cache.L1.NumCounters` | int64 | 10000000 | Ristretto 计数器数量（建议为 MaxCost 的 10 倍） |
| `Rpc.Cache.L1.MaxCost` | int64 | 268435456 | Ristretto 容量上限（字节）；>0 时优先于 MaxMemoryMB |
| `Rpc.Cache.L1.BufferItems` | int64 | 64 | Ristretto 写缓冲容量（越大写吞吐越高，内存占用略增） |
| `Rpc.Cache.L2.Enabled` | bool | `true` | L2 分布式缓存开关 |
| `Rpc.Cache.L2.Type` | string | `redis` | `redis` 或 `valkey`（二选一；协议兼容，共用 go-redis） |
| `Rpc.Cache.L2.Addresses` | []string | — | Redis/Valkey 地址列表（哨兵/集群填多个） |
| `Rpc.Cache.L2.Username` | string | `""` | ACL 用户名（Redis 6+ / Valkey） |
| `Rpc.Cache.L2.Password` | string | `""` | 密码 |
| `Rpc.Cache.L2.DB` | int | `0` | 库号 |
| `Rpc.Cache.L2.PoolSize` | int | 200 | 连接池大小 |
| `Rpc.Cache.L2.DialTimeout` | duration | `0` | 拨号超时（0=go-redis 默认 3s；建议 5s） |
| `Rpc.Cache.L2.ReadTimeout` | duration | `0` | 读超时（0=go-redis 默认 3s） |
| `Rpc.Cache.L2.WriteTimeout` | duration | `0` | 写超时（0=go-redis 默认 3s） |
| `Rpc.Cache.L2.TLS` | bool | `false` | TLS 开关（公网/云托管建议开启） |
| `Rpc.Cache.Bloom.ExpectedKeys` | uint64 | 1000000 | 布隆预期 key 总量 |
| `Rpc.Cache.Bloom.FalsePositiveRate` | float64 | 0.01 | 布隆目标假阳性率 |

> **L1 初始化失败降级**：Ristretto 初始化失败时自动降级为 no-op（仅 L1 不可用），进程不崩溃。
>
> **L2 后端说明**：`redis` 与 `valkey` 共用 go-redis `UniversalClient`，切换只需改 `Type` 字段。`DialTimeout/ReadTimeout/WriteTimeout/TLS` 原样透传。超时字段未配置时使用 go-redis 默认值（3s），建议根据网络环境适当调大。
>
> **布隆容量说明**：位数组实现、只增不删。超过 `ExpectedKeys` 时假阳性率上升（穿透保护变弱），但**零假阴性**，不影响数据正确性。100 万 key / 1% 假阳性约 1.2 MB。

#### 2.2.3 `Rpc.MQ` — 消息队列

支持四种后端：`kafka`（sarama）/ `rocketmq`（rocketmq-client-go）/ `rabbitmq`（amqp091-go）/ `memory`（进程内环形队列）。

**各后端配置完全独立、互不互通**。顶层仅保留 `Enabled` + `Type`，所有连接参数均在各后端子段内定义。切换 Type 即启用对应后端，其余子段可保留不删。

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `Rpc.MQ.Enabled` | bool | `false` | 总开关（false=no-op） |
| `Rpc.MQ.Type` | string | `memory` | `kafka` / `rocketmq` / `rabbitmq` / `memory` |
| **Kafka 专用** | | | |
| `Rpc.MQ.Kafka.Brokers` | []string | — | broker 地址列表 |
| `Rpc.MQ.Kafka.ConsumerGroup` | string | `hc-framework` | 消费者组 ID |
| `Rpc.MQ.Kafka.Topic` | string | `hc.events` | 默认主题 |
| `Rpc.MQ.Kafka.RequiredAcks` | int | 1 | 0=不等待 / 1=leader / -1=全部副本 |
| `Rpc.MQ.Kafka.BatchSize` | int | 100 | 攒批条数 |
| `Rpc.MQ.Kafka.BatchBytes` | int | 1048576 | 攒批字节上限 |
| **RocketMQ 专用** | | | |
| `Rpc.MQ.RocketMQ.NameServer` | []string | — | NameServer 地址列表 |
| `Rpc.MQ.RocketMQ.Group` | string | `hc-framework` | 组名 |
| `Rpc.MQ.RocketMQ.Retry` | int | 3 | 发送重试次数 |
| `Rpc.MQ.RocketMQ.Topic` | string | `hc.events` | 默认主题 |
| `Rpc.MQ.RocketMQ.AccessKey` | string | `""` | ACL 密钥 |
| `Rpc.MQ.RocketMQ.SecretKey` | string | `""` | ACL 密钥 |
| `Rpc.MQ.RocketMQ.Namespace` | string | `""` | 命名空间（如阿里云 ONS 实例 ID） |
| **RabbitMQ 专用** | | | |
| `Rpc.MQ.RabbitMQ.URL` | string | `amqp://guest:guest@127.0.0.1:5672/` | 完整 amqp 连接串 |
| `Rpc.MQ.RabbitMQ.Exchange` | string | `hc.events` | 交换机名 |
| `Rpc.MQ.RabbitMQ.ExchangeType` | string | `topic` | `direct` / `topic` / `fanout` |
| `Rpc.MQ.RabbitMQ.Queue` | string | `""` | 队列名（空按 topic 派生） |
| `Rpc.MQ.RabbitMQ.RoutingKey` | string | `hc.events` | 默认路由键 |
| `Rpc.MQ.RabbitMQ.Topic` | string | `hc.events` | 默认 routing key |
| `Rpc.MQ.RabbitMQ.Prefetch` | int | 1 | QoS 预取条数 |
| **Memory 专用** | | | |
| `Rpc.MQ.Memory.BufferSize` | int | 1024 | 通道缓冲大小 |

## 3. 配置一致性要点

1. **JWT 必须对称**：`Gateway.Auth.Jwt` 与 `Rpc.Jwt` 的 `SigningKey` / `Algorithm` / `Issuer` 必须完全一致。
2. **连接池预算**：单进程各库 `MaxOpenConns` 之和须低于 MySQL `max_connections`（默认 151）。默认值 20×4=80 留有安全余量；压测场景显式调大时需同步调 MySQL 参数。
3. **环境差异**：生产环境应通过环境变量/配置中心覆盖：
   - 各库 DSN → 真实连接串
   - `Gateway.Captcha` → 启用并配置真实 Provider
   - `SigningKey` → 从密钥管理注入，**不要提交真实密钥**
4. **sqlite 文件**：需保证进程对该路径有读写权限；容器化时挂载 volume。
5. **Metrics**：合并部署下网关与后端共享同一 prometheus 注册表，统一由 `:8080/metrics` 暴露。

## 4. 生成与校验

```bash
# 修改 hc.proto 后重新生成 pb 代码：
make gen

# 编译合并单进程二进制：
make build-server

# 校验配置可加载：
./bin/hc-server -f config/server.yaml
```
