# 902 · 配置参考（go-zero 版 · 合并单进程部署）

本文档对应真实的 `config/server.yaml`（合并部署单一配置文件）。所有字段由 `app/server/internal/config/config.go`（聚合 `app/gateway/api/config` 与 `app/rpc/config`）解析。

---

## 1. 合并配置总览（`config/server.yaml`）

合并部署使用**单一配置文件**，含两个顶层块：

- `Gateway:` —— 网关配置（`rest.RestConf` + `Auth` / `Captcha` / `Security` / `Prometheus` / `Log`）
- `Rpc:` —— 后端配置（`Name` / `DB` / `Jwt` / `BcryptCost` / `GoogleOAuth` / `Idle` / `Metrics` / `Log` / `Telemetry`）

```yaml
# ===== 网关 (REST :8080) =====
Gateway:
  Name: hc-gateway
  Host: 0.0.0.0
  Port: 8080

  # JWT 校验配置（与 Rpc 签发共用同一套密钥/算法/issuer）
  Auth:
    Jwt:
      Algorithm: HS256
      SigningKey: "<32+ 字节随机密钥>"
      Issuer: hc-framework
      AccessTTL: 2h
      RefreshTTL: 168h

  # 验证码防水墙（false 时跳过校验）
  Captcha:
    Enabled: false
    Provider: none            # none / turnstile / recaptcha / hcaptcha / tencent
    SiteKey: ""
    SecretKey: ""
    AppID: ""

  # IP 限频（进程内窗口，单实例有效）
  Security:
    IPLimitEnabled: false
    IPLimitPerMinute: 30

  # 日志格式（go-zero logx，内嵌于 RestConf.Log）
  Log:
    ServiceName: hc-gateway
    Mode: console             # console / file / volume
    Encoding: plain           # json / plain
    TimeFormat: "2006-01-02T15:04:05.000"
    Level: info               # info / debug / warn / error
    Path: logs
    Rotation: size            # size / time
    KeepDays: 7
    MaxSize: 256
    Compress: false

  # 网关已在路由中注册 GET /metrics，监听地址为 Host:Port（即 :8080/metrics）
  Prometheus:
    Host: 0.0.0.0
    Port: 9100

# ===== Rpc 后端（同进程，不再暴露 gRPC）=====
Rpc:
  Name: hc.rpc

  # 数据源（sqlite 零依赖启动；生产用 mysql/postgres）
  DB:
    Driver: sqlite            # sqlite / mysql / postgres
    Dsn: "./data/hc.db"      # mysql/postgres 用完整连接串

  # JWT 签发（与网关校验共用同一套密钥/算法/issuer，保证 token 互通）
  Jwt:
    Algorithm: HS256
    SigningKey: "<32+ 字节随机密钥>"
    Issuer: hc-framework
    AccessTTL: 2h
    RefreshTTL: 168h
    PrivateKeyPath: ""       # RS256 时使用
    PublicKeyPath: ""

  # 密码哈希成本（0=默认12；压测建议4-6，生产12+）
  BcryptCost: 4

  # Google OAuth（未配置时 /auth/google 返回第三方服务未配置错误）
  GoogleOAuth:
    ClientID: ""
    ClientSecret: ""
    RedirectURI: "http://localhost:8080/api/v1/auth/google"

  # 挂机业务参数
  Idle:
    MaxActiveDevices: 3
    PointsPerMinute: 10
    DailyPointsLimit: 14400

  # 日志格式（go-zero logx）
  Log:
    ServiceName: hc-rpc
    Mode: console
    Encoding: plain
    TimeFormat: "2006-01-02T15:04:05.000"
    Level: info
    Path: logs
    Rotation: size
    KeepDays: 7
    MaxSize: 256
    Compress: false

  # 链路追踪
  Telemetry:
    Name: hc.rpc

  # 链路追踪
  Telemetry:
    Name: hc.rpc
```

## 2. 字段说明

### 2.1 Gateway 块

| 字段 | 类型 | 默认/示例 | 说明 |
|------|------|-----------|------|
| `Gateway.Name` | string | `hc-gateway` | 服务名 |
| `Gateway.Host` / `Port` | string/int | `0.0.0.0` / 8080 | HTTP REST 入口 |
| `Gateway.Auth.Jwt.*` | — | — | JWT 校验参数，**必须与 Rpc.Jwt 对称** |
| `Gateway.Captcha.Enabled` | bool | false | false 跳过验证码校验 |
| `Gateway.Captcha.Provider` | string | `none` | 验证码 Provider 类型 |
| `Gateway.Security.IPLimitEnabled` | bool | false | IP 限频开关 |
| `Gateway.Security.IPLimitPerMinute` | int | 30 | 单 IP 每分钟最大请求数 |
| `Gateway.Log.*` | — | — | 日志（go-zero logx），见上方注释 |
| `Gateway.Prometheus.Host/Port` | — | `0.0.0.0`/9100 | 配置锚点（go-zero 已废弃的 push 模式，本项目未启用）；网关 `/metrics` 实际监听 `Gateway.Host:Gateway.Port` |

### 2.2 Rpc 块

| 字段 | 类型 | 默认/示例 | 说明 |
|------|------|-----------|------|
| `Rpc.Name` | string | `hc.rpc` | 服务名 |
| `Rpc.DB.Driver` | string | `sqlite` | `sqlite` / `mysql` / `postgres` |
| `Rpc.DB.Dsn` | string | `./data/hc.db` | sqlite 路径或 DB 连接串 |
| `Rpc.Jwt.*` | — | — | JWT 签发参数，**必须与 Gateway.Auth.Jwt 对称** |
| `Rpc.Jwt.PrivateKeyPath/PublicKeyPath` | string | `""` | RS256 时填写 |
| `Rpc.BcryptCost` | int | 4（压测）/12（生产） | 密码哈希成本 |
| `Rpc.GoogleOAuth.*` | — | — | Google OAuth 凭据 |
| `Rpc.Idle.MaxActiveDevices` | int | 3 | 单用户最大活跃设备数（超过报 `maximum active devices reached`） |
| `Rpc.Idle.PointsPerMinute` | int | 10 | 挂机每分钟积分 |
| `Rpc.Idle.DailyPointsLimit` | int64 | 14400 | 每日挂机积分上限 |
| `Rpc.Telemetry.Name` | string | `hc.rpc` | 链路追踪服务名 |
| `Rpc.Log.*` | — | — | 日志（go-zero logx） |

#### 2.2.1 `Rpc.Databases` — 多库模式（可选）

配置该块后走多库工厂 `dbclient.Factory`，与单库 `Rpc.DB` 二选一。

| 字段 | 类型 | 说明 |
|------|------|------|
| `Rpc.Databases.<name>.Driver` | string | `sqlite` / `mysql` / `postgres`(`postgresql`) / `mongodb` / `clickhouse` / `elasticsearch` |
| `Rpc.Databases.<name>.Dsn` | string | 通用连接串（vendor 段缺省时的回退值） |
| `Rpc.Databases.<name>.Mysql.Master` | string | MySQL 专用 DSN，**优先于顶层 `Dsn`** |
| `Rpc.Databases.<name>.Postgres.Master` | string | PostgreSQL 专用 DSN，**优先于顶层 `Dsn`** |
| `Rpc.Databases.<name>.MaxOpenConns` | int | 顶层连接池上限 |
| `Rpc.Databases.<name>.MaxIdleConns` | int | 顶层空闲连接数 |
| `Rpc.Databases.<name>.ConnMaxLifetime` | duration | 顶层连接最大存活时间 |
| `Rpc.Databases.<name>.<vendor>.MaxOpenConns` 等 | — | vendor 段连接池，**非 0 时覆盖顶层同名字段** |
| `Rpc.Databases.<name>.PoolLabel` | string | `db_pool_*` 指标的 `db` 标签，缺省取库名 |

> **解析优先级**：与 `Driver` 匹配的 vendor 段 > 顶层通用字段。该解析在配置层 `Databases.ToSpecs()` 中完成后再交给 `common/dbclient`（见 `docs/901` §2.1 分层依赖约束）。某个库解析失败只跳过该库并打 error 日志，不影响其余库装配。

#### 2.2.2 `Rpc.Cache` — 多级缓存

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `Rpc.Cache.Enabled` | bool | `true` | 缓存总开关 |
| `Rpc.Cache.L1.Enabled` | bool | `true` | L1 进程内缓存（Ristretto）。**初始化失败时自动降级为 no-op（仅 L1 不可用，进程不崩溃）**，与 L2 的惰性降级行为一致 |
| `Rpc.Cache.L1.MaxMemoryMB` | int | 256 | L1 内存上限 |
| `Rpc.Cache.L1.DefaultTTL` | duration | `5m` | L1 默认 TTL |
| `Rpc.Cache.L1.NumCounters` | int64 | 10000000 | Ristretto 计数器数量（**仅 L1 为 Ristretto 时生效**） |
| `Rpc.Cache.L1.MaxCost` | int64 | 268435456 | Ristretto 容量上限（字节，**仅 L1 为 Ristretto 时生效**） |
| `Rpc.Cache.L2.Enabled` | bool | `true` | L2 分布式缓存 |
| `Rpc.Cache.L2.Type` | string | `redis` | L2 类型 |
| `Rpc.Cache.L2.Addresses` | []string | — | Redis 地址列表 |
| `Rpc.Cache.L2.PoolSize` | int | 200 | Redis 连接池 |
| `Rpc.Cache.Bloom.ExpectedKeys` | uint64 | 1000000 | 布隆预期 key 总量 |
| `Rpc.Cache.Bloom.FalsePositiveRate` | float64 | 0.01 | 布隆目标假阳性率 |

> **布隆容量说明**：布隆过滤器用于缓存穿透保护，采用位数组实现、**只增不删**。实际插入量超过 `ExpectedKeys` 时假阳性率上升（穿透保护变弱），但**不会产生假阴性**，故不影响数据正确性。默认 100 万 key / 1% 假阳性约占用 1.2 MB（约 9.6 bit/key）。

## 3. 配置一致性要点

1. **JWT 必须对称**：`Gateway.Auth.Jwt` 与 `Rpc.Jwt` 的 `SigningKey` / `Algorithm` / `Issuer` 必须完全一致，否则网关签发的 token 在后端解析失败。
2. **环境差异**：生产环境应通过环境变量 / 配置中心覆盖：
   - `Rpc.DB.Dsn` → MySQL/PostgreSQL 连接串
   - `Gateway.Captcha` → 启用并配置真实 Provider（多实例建议 Redis 版）
   - 各类 `SigningKey` → 从密钥管理注入，**不要提交真实密钥**
3. **sqlite 文件**：默认 `./data/hc.db`，需保证进程对该路径有读写权限；容器化时挂载 volume。
4. **Metrics**：合并部署下网关与后端共享同一 prometheus 注册表，统一由 `:8080/metrics` 暴露，Prometheus 只需 scrape 这一个端点（service label 区分网关/后端）。

## 4. 生成与校验

```bash
# 修改 hc.proto 后重新生成 pb 代码：
make gen

# 编译合并单进程二进制：
make build-server

# 校验配置可加载（启动时不报错即通过）：
./bin/hc-server -f config/server.yaml
```
