# 904 · 变更记录（go-zero 迁移）

> 本文件记录从 gin 单体重构为 go-zero（rest 网关 + 单一领域 rpc）过程中的**关键架构决策、已实现项、与 gin 版的差异、以及尚未实现的能力**。
> 迁移背景与动机见 [900_go-zero迁移说明.md](900_go-zero迁移说明.md)。

---

## 1. 架构决策（已落地）

| # | 决策 | 理由 |
|---|------|------|
| D1 | 5 微服务合并为 **1 个 hc-rpc** | 降低运维复杂度；域边界清晰（proto 方法按域前缀），后续可平滑拆分 |
| D2 | 域间协作改为**进程内函数调用** | 合并后无需跨进程；`settle/AddPoints/DeductPoints/bumpProgress` 直接调用对应 `*Logic` |
| D3 | 数据层用 **gorm + sqlite** 起步 | 零外部依赖即可跑通；生产切 mysql/postgres 仅需改 `DataSource` |
| D4 | 移除 Redis 强依赖 | 验证码用可插拔 `CaptchaProvider`（默认 memory）；活跃会话改为 DB 表 `idle_records` |
| D5 | 错误码经 **grpc status** 跨进程传递 | `errorx.New(code,msg)` 编码为 `status.Error`；网关 `Code()/Msg()` 还原 |
| D6 | 网关仅做**协议转换 + 鉴权 + 统一响应** | 业务逻辑全部下沉后端；handler 极薄（解析→logic→响应） |
| D7 | 网关 `JwtAuth` 中间件注入 `user_id` | 后端所有请求携带 `user_id`，避免重复解析 token |
| D8 | **网关与后端合并为单进程 `hc-server`** | 移除跨进程 gRPC 与 etcd 服务发现；网关通过进程内 `LocalHcClient` 直接调用后端 logic，仅对外暴露 REST(:8080)，Prometheus 指标由同一端口的 `/metrics` 统一暴露 |

---

## 2. 已实现能力（与代码一致）

- ✅ rest 网关（go-zero `rest`）+ 单一后端（合并 user/idle/task/shop 四域）
- ✅ 合并单进程 `hc-server`：网关通过进程内 `LocalHcClient` 调用后端 logic，无需 gRPC 网络与 etcd
- ✅ 认证：邮箱注册/登录、Google OAuth、refresh token、改密（旧 token 失效）
- ✅ 用户资料 + 积分账户（`AddPoints` / `DeductPoints` 进程内）
- ✅ 多设备挂机：start（幂等）/ heartbeat（5 分钟超时结算）/ stop / stop-device / status / records
- ✅ 挂机结算：时长→积分，写入 `idle_daily_points` + 入账
- ✅ 任务：列表/进度/领取（事件驱动 `ReportProgress`）
- ✅ 商城：商品分页、积分兑换（扣款+扣库存+建单单事务）、订单、抢购活动（限量入库+事务行锁）
- ✅ 验证码：内存 Provider（可插拔 Redis）
- ✅ 网关 IP 限频（内存滑动窗口）、JWT 鉴权、统一响应
- ✅ 可观测：go-zero 内置 Prometheus 指标（**需在 `main.go` 调用 `prometheus.Enable()` 启用**，统一经 `:8080/metrics` 暴露）、链路追踪、日志
- ✅ 优雅关闭
- ✅ k6 压测脚本（auth/idle/shop/flash/mixed/ws）
- ✅ 启动 seed（自动建表 + 种子任务/商品）

## 3. 与 gin 版的关键差异（已确认）

| 能力 | gin 版 | go-zero 版（本分支） |
|------|--------|---------------------|
| 结算方式 | 事件驱动 + 定时结算 | **请求驱动、进程内同步结算** |
| 在线会话 | Redis 活跃会话集 + 心跳 | DB `idle_records`（status=active） |
| 限流 | 网关 + RPC 多 middleware（leakyBucket 等） | 网关 IP 滑动窗口（内存） |
| 熔断 | Resilience4j 显式熔断器 | go-zero 内置 Breaker（客户端） |
| 邮件/异步 | 异步邮件、事件总线 | **未实现** |
| Redis 缓存 | 双写缓存 | 可选（验证码插拔），业务不强依赖 |
| 服务数 | 5 微服务 | **1 个进程 `hc-server`**（网关 + 后端同进程，仅暴露 REST，指标经 `/metrics` 统一暴露） |

> 注意：gin 版文档（100-800 系列）中涉及的 Redis 业务缓存、事件总线、邮件、Kafka/RabbitMQ 消息驱动结算等，在 go-zero 版**尚未实现**，相关文档仅作历史参考，不应作为本分支行为依据。

## 4. 已知限制 / 待完善（TODO）

- ⬜ 生产数据库迁移：`migrations/` 提供 mysql/postgres 脚本，但 seed 当前面向 sqlite；需验证生产 DDL 一致性。
- ⬜ Redis 验证码 Provider：接口已留 `Store: redis`，但仅 memory 实现已验证。
- ⬜ 邮件/通知：无异步发信能力（gin 版的注册欢迎信等未迁移）。
- ⬜ 多实例一致性：当前为单 rpc 进程；验证码 memory、idle 结算均在进程内，水平扩展需引入 Redis / 分布式锁。
- 🟢 单元测试覆盖（持续完善中）：已补充 `common/jwt`、`common/errorx`、`common/bcrypt` 三个安全关键包，以及 `app/rpc/logic`（settle/accumulateDaily 资金结算路径，sqlite in-memory 集成测试）、`app/gateway/api/middleware`（JWT 鉴权、IP 限频、验证码中间件）。剩余待补：`app/rpc/logic` 其余业务 logic（登录/兑换/抢购等）、`common/gormx`、`common/model` 校验。
- ⬜ K8s 编排：`deployments/` 仅有监控 + 消息队列示例，正式部署 yaml 待补。
- ⬜ WebSocket：`scripts/k6/ws.js` 存在，但网关/rpc 当前无 ws 端点（heartbeat 走 HTTP）。
