# 904 · 变更记录(go-zero 版)

本文件记录 go-zero 重构(分支 `feature/go-zero-migration`)的主要演进。

## v0.2 · 单 rpc 架构(本次)

**变更**:4 个领域 rpc(user/idle/task/shop)合并为 1 个 `hc-rpc`。

- 删除 `app/{user,idle,task,shop}/rpc`,新增 `app/rpc`(契约 `hc.proto`,26 个 rpc 方法,方法名按域加前缀 `Idle*`/`Task*`/`Shop*`)。
- 进程数由 5 降为 2:网关 + 单一 rpc;域间协作(积分增减、任务进度)由跨 rpc 改为**进程内调用**(`settle`/`claim`/`redeem`/`flashredeem` 直接构造对应 logic)。
- 网关仅持有 `HcRpc` 一个 client;`gateway.yaml` 的 `UserRpc/IdleRpc/TaskRpc/ShopRpc` 收敛为 `HcRpc`。
- 挂机结算新增上报 `daily_idle_30`/`weekly_idle_300` 任务进度(行为增强)。
- 修复遗留 bug:user 域 `GoogleOAuth` 的 server/client 返回类型与 proto(`GoogleOAuthResponse`)不一致;合并后统一。
- 同步用户修正:user 域改用专用响应类型(`ChangePasswordResponse`/`GetProfileResponse`/`UpdateProfileResponse`、`AddPoints/DeductPointsResponse` 含 `user_id`)、`RegisterRequest` 字段序、`common/errorx` 改为 grpc status 编解码、`common/response` 的 trace API。
- 文档:新增 901 API 参考 / 902 配置参考 / 903 架构与启动 / 904 变更记录,更新 README。

**影响**:HTTP 契约不变(网关统一响应与字段名兼容);仅部署形态与 rpc 内部实现变化。
`make gen` 需重新生成 `app/rpc/hc/hc.pb.go`。

## v0.1 · 多 rpc 架构(上一版,已被 v0.2 取代)

- gin 单体重构为 go-zero:rest 网关 + user/idle/task/shop 四个领域 rpc(5 进程)。
- 26 条 HTTP 路由契约与原 gin 版完全兼容(统一响应、分页、错误码、JWT 算法)。
- 核心闭环:认证/用户/挂机/任务/商城/抢购;go-zero 内置治理(熔断/追踪/指标/优雅关闭)。
- 已知取舍:三级缓存、MQ、WebSocket、管理端、配置热更新、Redis 限流暂缓(见 900 §6)。
