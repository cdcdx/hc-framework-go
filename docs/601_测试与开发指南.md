# 测试与开发指南（Testing & Development Guide）

本文档从根 `README.md` 下沉并扩展，汇总**本地开发、测试与贡献流程**。开发规范与交付物见 [001_需求.md](./001_需求.md) / [002_需求规格说明书.md](./002_需求规格说明书.md)；接口契约见 [201_API参考.md](./201_API参考.md)；配置见 [202_配置参考.md](./202_配置参考.md)。

## 一、开发环境

- Go ≥ 1.25
- （可选）Redis 7.x / Valkey 8.x、MySQL 8.x / PostgreSQL 16.x
- **零依赖启动**：`make run` 以 SQLite 直接运行，无需任何中间件。

常用 `make` 命令：

```bash
make build        # 编译
make run          # 运行
make test         # 测试（go test -race ./...）
make test-idle    # 仅跑挂机相关用例
make lint         # golangci-lint 代码检查
make docker-build # Docker 构建
make clean        # 清理构建产物
```

## 二、代码规范

- 遵循 Go 官方 [Code Review Comments](https://github.com/golang/go/wiki/CodeReviewComments)，本地 `make lint`（依赖 [golangci-lint](https://golangci-lint.run/)）。
- **接口优先**：所有 Service / Repository 按接口设计，依赖通过构造函数注入。
- **三层架构**：`Handler → Service → Repository`。
- **API 注解**：接口添加 Swagger 注解，`swag init` 生成 `swagger/`。

## 三、添加一个新功能

1. 在 `internal/model/` 定义数据模型。
2. 在 `internal/repository/` 实现数据访问。
3. 在 `internal/service/` 实现业务逻辑。
4. 在 `internal/handler/` 实现 HTTP 处理器。
5. 在 `internal/router/` 注册路由。
6. 添加 Swagger 注解与必要的单元测试。

## 四、Git 工作流

```
feature/* → PR → Code Review → squash merge → main
```

## 九、压力测试配置切换（SQLite → MySQL）

`make run` 默认用 `config/server.yaml`（SQLite）零依赖启动，适合功能验证与轻量压测。**SQLite 是单写者数据库（即使 WAL 模式下写事务仍串行）**，在 k6 高并发写场景（如 `MIXED_VUS=2000` 的混合负载、`SHOP_VUS=1000` 的兑换抢购）下，写请求会因写锁等待超时被服务端断开连接，客户端表现为 `Post ".../shop/redeem": EOF`，并伴随 k6 指标 `'null' is an invalid value for metric 'mixed_write_ok'` 的告警。这不是业务代码缺陷，而是存储选型与负载不匹配。

**压测高并发写必须用 MySQL/PostgreSQL。** 已提供专用配置 `config/server.mysql.yaml`：

```bash
# 1. 切换为 MySQL 压测配置
cp config/server.mysql.yaml config/server.yaml

# 2. 按压测环境修改 Mysql.Master 连接串（默认 127.0.0.1:3306，库名 hc_business/hc_users/hc_monitor/hc_logs）
#    示例: hc:password@tcp(127.0.0.1:3306)/hc_business?charset=utf8mb4&parseTime=true&loc=Local

# 3. 建库并执行迁移
bash scripts/migrate.sh

# 4. 启动服务后跑压测
make run
ADMIN_TOKEN=xxx bash k6-test.sh
```

`server.mysql.yaml` 已相对 `server.example.yaml` 做了压测适配：
- 四个库 `Driver: mysql`，连接池 `MaxOpenConns` 放大到 200（business/user）/100（monitor/log）；
- `Cache` 默认开启（L1 + L2 Redis），贴近读多写少真实场景，避免缓存关闭时所有读穿透到 DB；
- `FlashSale.Timeout` 由 3s 放宽到 10s，避免正常排队被误判超时。

> 注意：切回功能验证时记得把 `server.yaml` 还原为 SQLite 版本（`cp config/server.example.yaml config/server.yaml`）。
